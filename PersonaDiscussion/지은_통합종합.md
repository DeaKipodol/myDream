## 2. 프로젝트 이해: "AI 생각 작업공간"

### 2-1. 서비스 핵심 컨셉

> **"트리 구조 대화 관리 시스템"** - 여러 대화 경로를 동시에 관리하고, 참조하고, 병합할 수 있는 AI 상담 도구

**핵심 차별점**:
1. **트리 구조**: 대화가 분기되어 여러 경로로 발전
2. **경로 전환**: 노드 클릭 = 컨텍스트 전환
3. **다중 관점**: 여러 AI 페르소나가 각자 답변

## 3. 토론 주제 정리

### 3-1. 핵심 토론 주제

> **"AI 생각 작업공간에 GPT 스타일 사이드패널을 추가하여 설정/계정 관리를 정리할 것인가?"**

### 3-2. 세부 토론 안건

1. **사이드패널 도입 여부**: 현재 엣지 독 + 탭 시스템을 유지할 것인가, 사이드패널을 추가할 것인가?
2. **기능 배치 전략**: 설정/계정/히스토리를 어디에 배치할 것인가?
3. **제품 정체성**: "트리 구조 생각 도구"라는 정체성과 사이드패널이 충돌하지 않는가?
4. **인지 부하**: 엣지 독 + 사이드패널이 과밀하지 않은가?

## 4. 3인 페르소나 관점 요약

### 4-1. 민수 (사용자 심리) 핵심 포인트

| 주제 | 분석 |
|------|------|
| **설정/계정 접근 심리** | 낮은 빈도, 호기심 영역 → 2-tap 허용 |
| **인지 부하** | 네비게이션 4개 = 과밀, 힉의 법칙 위반 가능 |
| **GPT 멘탈 모델** | 사용자가 이미 학습한 패턴, 활용 가치 있음 |
| **제안** | 헤더 우측 드롭다운 (경량화) 권장 |

### 4-2. 수진 (시각 디자인) 핵심 포인트

| 주제 | 분석 |
|------|------|
| **Figure-Ground** | 현재 엣지 독 = 명확한 분리, 사이드패널 추가 시 혼란 가능 |
| **시각적 위계** | 설정/계정 = 4-5순위 (가장 낮음), 눈에 띄게 배치할 필요 없음 |
| **Progressive Disclosure** | 아이콘 → 드롭다운 → 상세 페이지 패턴 적용 가능 |
| **제안** | 헤더 우측 아이콘 + 드롭다운 권장 |

### 4-3. 동현 (서비스 철학) 핵심 포인트

| 주제 | 분석 |
|------|------|
| **서비스 정체성** | "트리 구조 생각 도구" ≠ GPT "범용 AI 어시스턴트" |
| **설정/계정 본질** | 관리 기능, 핵심 아님, 숨겨도 됨 |
| **GPT 따라하기 우려** | 사이드패널 도입 시 정체성 희석 가능 |
| **제안** | 미니멀리즘 유지, 헤더 우측에 경량 배치 권장 |

## 5. 충돌 지점 분석

### 5-1. 찬반 정리

**사이드패널 도입 찬성**:
| 논거 | 근거 |
|------|------|
| GPT 멘탈 모델 활용 → 학습 비용 0 | 민수 |
| 모든 네비게이션이 한 곳 → 발견성 | 수진 |
| 기능 확장 시 확장성 | 일반적 |

**사이드패널 도입 반대**:
| 논거 | 근거 |
|------|------|
| 인지 부하 증가 (4개 네비게이션) | 민수 |
| Figure-Ground 혼란 (좌측 레이어 2개) | 수진 |
| 정체성 희석 ("GPT 클론") | 동현 |
| 엣지 독 = 시각적 정체성, 없어지면 손실 | 동현 |
| 설정/계정은 관리 기능, 별도 공간 불필요 | 동현 |

### 5-2. 주요 충돌

| 충돌 | 민수 | 수진 | 동현 |
|------|------|------|------|
| **멘탈 모델 vs 정체성** | GPT 패턴 활용 | 중립 | 정체성 유지 |
| **발견성 vs 미니멀리즘** | 중립 | 발견성도 중요 | 미니멀 우선 |
| **확장성 vs 현재 시스템** | 사이드패널이 확장적 | 엣지 독도 확장 가능 | 필요할 때 확장 |

### 5-3. 합의점

**3인 모두 동의**:
1. 설정/계정은 **빈도 낮음** → 2-tap 허용
2. 설정/계정은 **관리 기능** → 핵심/부가/확장과 분리
3. **헤더 우측 아이콘 + 드롭다운**이 가장 안전한 선택

## 8. 최종 결정 (가설)

### 8-1. 권장 결론

> **옵션 A: 헤더 우측 드롭다운**

**결정 이유**:
1. **정체성 유지**: 엣지 독 시스템 보존 → "트리 구조 생각 도구" 정체성
2. **인지 부하 최소화**: 기존 시스템 유지, 추가 요소 최소
3. **구현 용이**: Quick Win, 빠르게 적용 가능
4. **롤백 용이**: 실패해도 쉽게 되돌릴 수 있음
5. **3인 합의**: 민수, 수진, 동현 모두 이 방향에 동의

### 8-2. 구현 사양

```
┌──────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +     │  ⚙️  │  👤  │
└──────────────────────────────────────────────────┘
```

**설정 아이콘 (⚙️)**:
- 크기: 24px 아이콘, 44px 클릭 영역
- hover: 툴팁 "설정"
- 클릭: 드롭다운 메뉴
  - 테마 (라이트/다크)
  - 알림 설정
  - 도움말
  - 키보드 단축키

**계정 아이콘 (👤)**:
- 크기: 24px 아이콘, 44px 클릭 영역
- hover: 툴팁 "계정"
- 클릭: 드롭다운 메뉴
  - 계정 정보
  - 플랜/구독
  - 로그아웃

### 8-3. 조건부 결정

| 조건 | 결정 |
|------|------|
| 사용자 피드백에서 "설정 못 찾겠다" 다수 | 아이콘 시인성 강화 (크기/색상) |
| 사용자 피드백에서 "GPT처럼 해달라" 다수 | 옵션 C 재검토 |
| 기능 대폭 확장 예정 | 옵션 C 검토 |

### 8-4. 다음 단계

- [ ] 헤더 우측에 ⚙️ / 👤 아이콘 추가 (HTML)
- [ ] 클릭 시 드롭다운 메뉴 구현 (CSS + JS)
- [ ] 메뉴 항목 구현: 설정, 도움말, 계정 정보, 로그아웃
- [ ] 시인성 테스트 (사용자가 발견할 수 있는지)

### 11-3. 모듈 간 연동 문제

```
┌──────────────┐     ┌──────────────┐
│   모듈 B     │     │   모듈 C     │
│  (홈 화면)   │  X  │  (드롭다운)  │
└──────────────┘     └──────────────┘
      ↓                    ↓
   ModuleB            workspaceManager (fallback)
      ↓                    ↓
  localStorage         하드코딩 데이터
```

**문제**: 모듈 B는 `ModuleB`로 노출, 모듈 C는 `workspaceManager`를 찾음 → 연결 안됨

**해결 필요**:
```javascript
// 모듈 B에 추가 필요
window.workspaceManager = window.ModuleB;
window.router = window.ModuleB;
```

> UX/UI 전문가로서 시각 디자인, 인터랙션 디자인, 게슈탈트 원리에 특화
> 핵심 질문: "**어떻게** 보여야 하는가?"

## 1. 페르소나 프로필

**이름**: 수진
**직군**: UX/UI 전문가
**특화 분야**: 시각 디자인, 인터랙션, 레이아웃, 마이크로인터랙션
**다른 전문가와의 관계**: 민수(심리), 동현(철학), 지은(통합)과 함께 UX 토론 진행

### 분석 프레임워크

| 개념 | 설명 | 적용 |
|------|------|------|
| **Figure-Ground** | 주요 콘텐츠(Figure)와 부가 도구(Ground)의 분리 | 레이어 구분 |
| **시각적 위계** | 크기, 색상, 위치로 중요도 표현 | 버튼 강조 |

| **게슈탈트 원리** | 근접, 유사, 폐쇄 등 시각 인지 | 그룹핑 |

## 2. 프로젝트 이해: "AI 생각 작업공간"

### 2-1. 서비스 핵심 컨셉

> **"트리 구조 대화 관리 시스템"** - 여러 대화 경로를 동시에 관리하고, 참조하고, 병합할 수 있는 AI 상담 도구

**시각적 메타포**: 파일 시스템
- 노드 클릭 = 폴더 이동 (`cd` 명령어)
- 분기 = 새 폴더 생성
- 체크포인트 = 북마크

### 2-2. 핵심 UI 요소

1. **트리 시각화**: 대화 구조를 트리로 표현, 노드 클릭으로 경로 전환
2. **엣지 독**: 화면 가장자리에 붙어 "존재하지만 조용한" 상태
3. **다중 관점 패널**: 여러 AI 페르소나의 의견을 카드로 표시

### 2-3. 현재 UI 구조 (v3 엣지 독 시스템)

```
┌────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +                     │ ← 헤더
├────────────────────────────────────────────────┤
│    │                                       │   │
│ 🌳 │                                       │ 💡│ ← 좌우 엣지 독
│    │         대화 영역                     │   │
│    │                                       │ 🎭│
│    │                                       │ 📄│
├────────────────────────────────────────────────┤
│  [메시지 입력...] [➤]                          │
└────────────────────────────────────────────────┘
```

**엣지 독 동작**:
- Level 0: 아이콘만 보임 (48px)
- Level 1: hover → 라벨 표시
- Level 2: 클릭 → 패널 슬라이드

### 2-4. 이전 디자인 변화 히스토리 (교훈)

| 버전 | 변경 | 결과 | 교훈 |
|------|------|------|------|
| v0 | 하단 fixed 토글바 | ❌ 전송 버튼 가림 | 핵심 UI 가리면 안 됨 |
| v1 | 인라인 (입력 위) | ❌ 박스감 상실 | 부가 도구는 분리된 레이어 필요 |
| v2 | 헤더 우측 통합 | ❌ 정체 불명 | Figure-Ground 상실 |
| **v3** | **엣지 독** | ✅ 성공 | "숨기되 보이게" |

**도출된 디자인 원칙**:
1. **Figure-Ground 분리**: 부가 도구는 메인과 시각적으로 분리
2. **Progressive Disclosure**: 아이콘 → hover 라벨 → 클릭 패널
3. **행동 기반 배치**: 좌측=구조/과거, 우측=확장/미래
4. **헤더 통합 금지**: 네비게이션을 헤더에 합치면 정체성 상실

## 3. 시각 디자인 분석: GPT vs 우리 서비스

### 3-1. GPT 사이드패널 시각 구조

```
┌────────────────────────────────────────────────┐
│ [≡]  ChatGPT ▼   [메모리 가득 참]              │ ← 헤더
├────────────────────────────────────────────────┤
│ [사이드패널]  │                                │
│ 새 채팅      │                                │
│ 검색         │                                │
│ 이미지       │                                │
│ 앱           │         대화 영역              │
│ Codex        │                                │
│ GPT          │                                │
│ 프로젝트     │                                │
│ 내 채팅      │                                │
│ ─────────    │                                │
│ 👤 계정      │                                │
└────────────────────────────────────────────────┘
```

**시각적 특징**:
1. **단일 네비게이션 축**: 모든 네비게이션이 좌측에 집중
2. **명확한 Figure-Ground**: 사이드패널(Ground) vs 대화영역(Figure)
3. **토글 방식**: 열기/닫기로 공간 활용
4. **계층 구조**: 새 채팅 > 도구 > 프로젝트 > 히스토리 > 계정

### 3-2. 우리 서비스 시각 구조 (엣지 독)

```
┌────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +                     │ ← 헤더
├────────────────────────────────────────────────┤
│    │                                       │   │
│ 🌳 │                                       │ 💡│ ← 좌우 엣지 독
│    │         대화 영역                     │   │
│    │                                       │ 🎭│
│    │                                       │ 📄│
└────────────────────────────────────────────────┘
```

**시각적 특징**:
1. **분산된 네비게이션**: 상단(탭) + 좌측(트리) + 우측(관점)
2. **대칭 구조**: 좌우 균형 (구조 vs 확장)
3. **"조용한 존재감"**: 엣지에 붙어 존재하지만 방해 안 함
4. **Progressive Disclosure**: 필요할 때만 확장

### 3-3. 시각적 비교표

| 요소 | ChatGPT | AI 생각 작업공간 | 평가 |
|------|---------|------------------|------|
| **네비게이션 위치** | 좌측 집중 | 분산 (상/좌/우) | GPT가 명확 |
| **Figure-Ground** | 명확 (패널/콘텐츠) | 명확 (엣지 독/콘텐츠) | 동등 |
| **공간 활용** | 토글 시 좌측 확장 | 양쪽 슬라이드 | 우리가 유연 |
| **시각적 복잡도** | 중간 | 낮음 | 우리가 미니멀 |
| **설정/계정** | 사이드패널 하단 | 없음/불명확 | GPT가 명확 |
| **트리 표현** | 없음 | 🌳 엣지 독 | 우리만의 강점 |

## 4. 토론 주제 분석: 사이드패널 도입 시 시각적 영향

### 4-1. Figure-Ground 분리 검토

**현재 엣지 독 시스템**:
- 🌳(좌), 💡🎭📄(우)가 화면 가장자리에 "떠있음"
- 대화 영역(Figure)과 명확히 분리
- **유지해야 할 강점**

**사이드패널 추가 시 위험**:
```
┌──────────────────────────────────────────────┐
│ [≡] 🧠 AI 생각 │ 탭1 │ 탭2 │                 │
├──────────────────────────────────────────────┤
│ [사이드패널]│ 🌳 │                      │ 💡 │
│ 새 작업공간 │    │                      │    │
│ 히스토리    │    │    대화 영역         │ 🎭 │
│ 설정        │    │                      │ 📄 │
│ 계정        │    │                      │    │
└──────────────────────────────────────────────┘
          ↑    ↑
          두 개의 좌측 레이어 = Figure-Ground 혼란
```

**문제**: "사이드패널과 🌳 엣지 독 중 어느 게 부가 도구지?"

### 4-2. 시각적 위계 분석

**GPT 시각 위계** (좌측 사이드패널):
```
1순위: 새 채팅 버튼 (상단)
2순위: 도구 메뉴 (중간)
3순위: 히스토리 (하단)
4순위: 계정 (맨 하단)
```

**AI 생각 작업공간 현재 위계**:
```
1순위: 대화 영역 (중앙) - 가장 넓음
2순위: 입력창 (하단) - 항상 보임
3순위: 탭 (상단) - 작업공간 전환
4순위: 엣지 독 (좌우) - 조용하게 존재
```

**설정/계정의 적절한 위계**: 가장 낮음 (5순위)
- 눈에 띄게 배치할 필요 없음
- 찾으면 있는 정도

### 4-3. Progressive Disclosure 적용

**현재 엣지 독 패턴**:
```
Level 0: 아이콘만 (🌳, 💡)
Level 1: hover → 라벨 ("생각 트리", "관점 도구")
Level 2: 클릭 → 패널 슬라이드
```

**설정/계정에 적용**:
```
Level 0: 아이콘만 (⚙️, 👤)
Level 1: hover → 툴팁 ("설정", "계정")
Level 2: 클릭 → 드롭다운 메뉴
Level 3: 메뉴 항목 선택 → 모달/페이지
```

## 5. 디자인 제안

### 제안 A: 헤더 우측 아이콘 + 드롭다운 (권장)

```
┌──────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +     │  ⚙️  │  👤  │
└──────────────────────────────────────────────────┘
                                    ↓ 클릭 시
                              ┌────────────┐
                              │ 설정       │
                              │ 도움말     │
                              │ ────────── │
                              │ 계정 정보  │
                              │ 플랜       │
                              │ 로그아웃   │
                              └────────────┘
```

**시각적 장점**:
1. 기존 엣지 독 시스템과 **충돌 없음**
2. Figure-Ground **유지**
3. 미니멀한 시각적 복잡도 **유지**
4. GPT 헤더 우측 패턴과 유사 (메모리 상태 표시 위치)

**시각적 사양**:
- 아이콘 크기: 24px
- 클릭 영역: 44px (터치 타겟)
- 드롭다운 너비: 200px
- 그림자: 0 4px 12px rgba(0,0,0,0.15)

### 제안 B: 좌측 사이드패널 (🌳 흡수)

```
┌──────────────────────────────────────────────────┐
│ [≡] 🧠 AI 생각 │ 탭1 │ 탭2 │ +                   │
├──────────────────────────────────────────────────┤
│ + 새 작업공간  │                              │   │
│ ────────────   │                              │ 💡│
│ 🌳 생각 트리   │        채팅 영역             │   │
│   └ 노드1      │                              │ 🎭│
│   └ 노드2      │                              │ 📄│
│ ────────────   │                              │   │
│ 📁 히스토리    │                              │   │
│ ────────────   │                              │   │
│ ⚙️ 설정        │                              │   │
│ 👤 계정        │                              │   │
└──────────────────────────────────────────────────┘
```

**시각적 장점**:
1. 좌측 네비게이션 **통합** (트리 + 히스토리 + 계정)
2. 🌳 생각 트리가 더 넓은 공간 확보
3. GPT 멘탈 모델과 일치

**시각적 단점**:
1. **좌우 비대칭** (좌측 무겁고 우측 가벼움)
2. 엣지 독의 **"조용한 존재감" 상실**
3. 시각적 복잡도 **증가**
4. **Figure-Ground 혼란** (사이드패널 vs 우측 엣지 독)

### 제안 C: 설정 전용 바텀시트 (모바일 친화)

```
┌──────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +           │  ⚙️  │
├──────────────────────────────────────────────────┤
│    │                                         │   │
│ 🌳 │         대화 영역                       │ 💡│
│    │                                         │   │
├──────────────────────────────────────────────────┤
│  ⚙️ 클릭 시 바텀시트 슬라이드 업                │
│  ┌─────────────────────────────────────────┐    │
│  │ 설정 | 계정 | 도움말                    │    │
│  │ ─────────────────────────────────────── │    │
│  │ 테마: [라이트 ▼]  알림: [켜기 ▼]       │    │
│  └─────────────────────────────────────────┘    │
└──────────────────────────────────────────────────┘
```

**시각적 장점**:
1. 모바일과 데스크톱 **동일한 패턴**
2. 대화 영역 방해 최소화
3. 설정 전용 공간 확보

## 6. 시각 디자인 원칙 (이 프로젝트)

### 6-1. 도출된 원칙 (이전 토론에서)

1. **Figure-Ground 분리**: 부가 도구는 메인 콘텐츠와 시각적으로 분리
2. **Progressive Disclosure**: 아이콘 → hover 라벨 → 클릭 패널
3. **행동 기반 배치**: 좌측=구조/과거, 우측=확장/미래
4. **1-tap/2-tap 비대칭**: 빈도 높은 도구는 즉시, 낮은 도구는 폴더
5. **헤더 통합 금지**: 네비게이션을 헤더에 합치면 Figure-Ground 상실

### 6-2. 설정/계정에 적용

| 원칙 | 적용 |
|------|------|
| Figure-Ground | 설정/계정은 "부가 도구"로 분류 → 메인과 분리 |
| Progressive Disclosure | 아이콘 → 드롭다운 → 상세 페이지 |
| 빈도 기반 | 낮은 빈도 → 2-tap 허용 |
| 헤더 통합 금지 | 아이콘은 가능, 전체 메뉴를 헤더에 펼치면 안 됨 |

|---|------|------------|------|
| 1 | "마케팅 전략" 드롭다운이 초기 화면에서 눈에 안 띔 | **시각적 고아(orphan)** - 맥락 없이 혼자 존재 | 사용자 혼란 |
| 2 | 빈 작업공간 목록 | **Empty State 디자인 부재** - 흰 공간만 | 다음 행동 불명확 |
| 3 | 버튼 무반응 | **피드백 부재** - 시각적 상태 변화 없음 | 시스템 죽어보임 |

### 9-3. 시각적 분석

**"마케팅 전략" 드롭다운 문제**:
```
현재 상태:
┌─────────────────┐
│ 🧠 [마케팅 전략 ∨] ...
└─────────────────┘
    ↑
    "이게 뭐지? 이미 선택된 건가?"
```

**시각적 불일치**:
- 홈 화면 = "작업공간 목록"을 보여주는 뷰
- 헤더에 이미 "마케팅 전략"이 선택된 것처럼 표시
- **Figure-Ground 혼란**: 홈(배경)인데 특정 작업공간(전경)이 선택된 상태

**개선 방향**:
```
개선안 A: 홈에서는 드롭다운 숨기기
┌─────────────────┐
│ 🧠 AI 생각 작업공간    ⚙️ [DK]
└─────────────────┘

개선안 B: "작업공간 선택" 텍스트로 변경
┌─────────────────┐
│ 🧠 [작업공간 선택 ∨]   ⚙️ [DK]
└─────────────────┘
```

### 9-4. Empty State 디자인 필요

**현재**: 아무것도 없는 빈 공간
**필요**: 명확한 다음 행동 유도

```
┌────────────────────────────────────────────┐
│                                            │
│            📁                              │
│       아직 작업공간이 없습니다              │
│                                            │
│     첫 번째 생각 정리를 시작해보세요        │
│                                            │
│        [+ 새 작업공간 만들기]               │  ← Primary CTA
│                                            │
└────────────────────────────────────────────┘
```

### 9-5. 코드 수준 원인 (시각적 관점)

**모듈 B HTML 렌더링 문제**:
- `home-workspace-list` ID 요소에 카드가 렌더링되지 않음
- `home-empty-state` ID 요소도 표시되지 않음
- 결과: **시각적 피드백 0** → "시스템이 죽었나?"

**버튼 상태 문제**:
- `:active`, `:focus` 상태 스타일이 있어도 이벤트가 안 달려 있으면 무의미
- 클릭해도 시각적 변화 없음 → "고장난 것 같다"

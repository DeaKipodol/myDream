## 2. 프로젝트 이해: "AI 생각 작업공간"

### 2-1. 서비스 정체성 정의

> **"트리 구조 대화 관리 시스템"** - 여러 대화 경로를 동시에 관리하고, 참조하고, 병합할 수 있는 AI 상담 도구

**한 문장으로**: "생각을 분기하고 탐색하는 AI 도구"

**핵심 가치**:
1. **비선형 사고 지원**: 생각은 직선이 아님, 분기하고 병합함
2. **컨텍스트 보존**: 어디로 가든 맥락이 유지됨
3. **다각도 탐색**: 같은 지점에서 여러 방향을 시도할 수 있음

### 2-2. 기존 서비스와의 차이 (정체성 관점)

| 서비스 | 정체성 | 핵심 가치 |
|--------|--------|-----------|
| **ChatGPT** | 범용 AI 어시스턴트 | "무엇이든 물어보세요" |
| **Claude** | 사려 깊은 AI 파트너 | "깊이 있는 대화" |
| **Notion AI** | 작업 공간의 AI | "문서와 함께" |
| **AI 생각 작업공간** | **트리 구조 생각 도구** | **"분기하고 탐색하세요"** |

### 2-3. 기능 분류 (3-Layer + 관리)

| 레이어 | 기능 | 설명 | 없으면? |
|--------|------|------|---------|
| **핵심** | 대화 + 분기 | AI 대화, 트리 구조 생성 | 서비스 불가 |
| **부가** | 생각 트리 시각화 | 대화 구조 확인/전환 | 불편하지만 가능 |
| **확장** | 관점 도구 (페르소나, 문서) | 다양한 시각으로 사고 확장 | 없어도 기본 사용 가능 |
| **관리** | 설정, 계정, 도움말 | 시스템 레벨 조정 | 없어도 기본 사용 가능 |

### 2-4. 현재 UI 구조와 기능 배치

```
┌────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +                     │ ← 작업공간 관리
├────────────────────────────────────────────────┤
│    │                                       │   │
│ 🌳 │                                       │ 💡│
│부가│         핵심 (대화)                   │확장│
│    │                                       │ 🎭│
│    │                                       │ 📄│
├────────────────────────────────────────────────┤
│  [메시지 입력...] [➤]                          │ ← 핵심
└────────────────────────────────────────────────┘
          ↑
          관리 기능은 어디에? (현재 없음)
```

**현재 배치 철학**:
- **중앙**: 핵심 (대화)
- **좌측**: 부가 (구조 확인) - "과거/확인"
- **우측**: 확장 (관점 도구) - "미래/탐색"
- **관리**: ???

## 3. 서비스 철학 분석: GPT vs 우리 서비스

### 3-1. ChatGPT의 정체성

> "범용 AI 어시스턴트" - 무엇이든 할 수 있는 만능 도구

**기능 분류**:
| 레이어 | 기능 |
|--------|------|
| 핵심 | 대화 |
| 부가 | 채팅 히스토리 |
| 확장 | 이미지 생성, Codex, GPT 빌더, 앱 |
| 관리 | 설정, 계정, 메모리 |

**사이드패널의 역할**:
- "대화 외의 모든 것"의 집합소
- 부가 + 확장 + 관리를 한 곳에

### 3-2. AI 생각 작업공간의 정체성

> "트리 구조 생각 도구" - 분기하고 탐색하는 사고 지원

**기능 분류**:
| 레이어 | 기능 |
|--------|------|
| 핵심 | 대화 + 분기 |
| 부가 | 생각 트리 (🌳) |
| 확장 | 관점 도구 (💡🎭📄) |
| 관리 | 설정, 계정 (미구현) |

**엣지 독의 역할**:
- 좌측: 부가 (구조 확인)
- 우측: 확장 (관점 탐색)
- 정체성: "트리 기반"이라는 것을 시각화

### 3-3. 정체성 비교

| 측면 | ChatGPT | AI 생각 작업공간 |
|------|---------|------------------|
| **핵심 가치** | 범용 AI 답변 | 사고 구조화 |
| **차별점** | 다양한 도구 통합 | 트리 기반 분기 |
| **메타포** | 만능 비서 | 생각 노트 |
| **부가 기능 접근** | 사이드패널 (통합) | 엣지 독 (분리) |
| **시각적 정체성** | 사이드패널 | 엣지 독 |

## 4. 토론 주제 분석: 사이드패널 도입의 철학적 함의

### 4-1. "GPT를 따라하면 GPT가 된다"

**문제 제기**:
> 사이드패널을 도입하면 우리 서비스가 "GPT 클론"처럼 보이지 않을까?

**고려 사항**:
1. 사용자가 "이건 GPT랑 뭐가 다르지?"라고 느끼면 **실패**
2. 엣지 독은 "트리 구조 도구"라는 **시각적 정체성**
3. 사이드패널은 "범용 AI"의 **시각적 정체성**

**반론**:
1. 좋은 UI 패턴은 차용해도 됨
2. 내용(기능)이 다르면 형식(UI)이 유사해도 OK
3. 사용자 편의가 정체성보다 중요할 수 있음

### 4-2. 설정/계정의 본질적 역할

**질문**: 설정/계정은 "트리 구조 생각 도구"에서 어떤 역할인가?

| 기능 | 역할 | 본질 |
|------|------|------|
| 설정 | 도구의 작동 방식 조정 | 시스템 레벨 |
| 계정 | 사용자 식별, 데이터 저장 | 시스템 레벨 |
| 도움말 | 사용 방법 안내 | 시스템 레벨 |

**결론**:
- 핵심 기능 아님 (설정 없어도 생각 정리 가능)
- **관리 기능** (시스템 레벨)
- 빈도 낮음 (매일 접근 X)
- **눈에 띄게 배치할 필요 없음**

### 4-3. 엣지 독 = 시각적 정체성

**엣지 독이 전달하는 메시지**:
1. "이 서비스는 트리 구조야" (🌳이 항상 보임)
2. "좌우에 도구가 있어" (양쪽 대칭)
3. "채팅이 중심이야" (중앙에 대화)

**사이드패널로 바꾸면?**:
1. "이 서비스는 GPT 같은 거야" (사이드패널 = GPT 연상)
2. "좌측에 모든 게 있어" (좌측 집중)
3. 🌳 트리가 사이드패널에 묻히면 "트리 기반"이라는 정체성 약화

### 4-4. 기능 배치 철학: 3-Layer + 관리

```
┌─────────────────────────────────────────────────┐
│                    헤더 (관리)                   │
│                 ⚙️ 설정  👤 계정                │
├───────────┬────────────────────────┬────────────┤
│           │                        │            │
│  좌측     │       중앙             │   우측     │
│  (부가)   │       (핵심)           │   (확장)   │
│  🌳       │       채팅             │   💡🎭📄   │
│  구조     │       대화/분기        │   관점     │
│           │                        │            │
└───────────┴────────────────────────┴────────────┘
```

**배치 원칙**:
| 기준 | 질문 | 배치 |
|------|------|------|
| **본질** | 이 기능 없이 서비스가 성립하는가? | No → 핵심 (중앙) |
| **빈도** | 매일 사용하는가? | Yes → 1-tap 접근 |
| **성격** | 과거/확인인가, 미래/탐색인가? | 과거 → 좌측, 미래 → 우측 |
| **레벨** | 콘텐츠 레벨인가, 시스템 레벨인가? | 시스템 → 헤더 |

## 5. 철학적 제안

### 제안 A: 미니멀리즘 - 헤더 우측 아이콘 (권장)

> "관리 기능은 있되, 눈에 띄지 않게"

```
┌──────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +          [⚙️] [👤]  │
├──────────────────────────────────────────────────┤
│    │                                         │   │
│ 🌳 │         채팅 영역                       │ 💡│
│    │                                         │   │
└──────────────────────────────────────────────────┘
```

**철학적 근거**:
1. **"도구는 눈에 띄지 않아야 한다"**: 설정/계정은 메인 경험을 방해하면 안 됨
2. **미니멀리즘**: 필요한 기능만, 필요할 때만
3. **정체성 유지**: 엣지 독 시스템 = 우리의 시각적 정체성
4. **관리 기능 분리**: 핵심/부가/확장과 관리를 다른 영역에

### 제안 B: 기능 통합 - 좌측 사이드패널로 전환

> "GPT 패턴을 수용하되, 우리 콘텐츠로 채우기"

```
┌──────────────────────────────────────────────────┐
│ [≡] 🧠 AI 생각 │ 탭1 │ 탭2 │ +                   │
├──────────────────────────────────────────────────┤
│ + 새 작업공간  │                              │   │
│ ────────────   │                              │ 💡│
│ 🌳 생각 트리   │        채팅 영역             │   │
│   └ 노드들...  │                              │ 🎭│
│ ────────────   │                              │ 📄│
│ 📁 히스토리    │                              │   │
│ ────────────   │                              │   │
│ ⚙️ 설정        │                              │   │
│ 👤 계정        │                              │   │
└──────────────────────────────────────────────────┘
```

**철학적 근거**:
1. **익숙함의 가치**: 사용자가 이미 학습한 패턴 활용
2. **기능 발견성**: 모든 기능이 한 곳에 → 찾기 쉬움
3. **진화의 수용**: UI 트렌드를 따르는 것도 전략

**철학적 우려**:
1. **정체성 희석**: "GPT랑 뭐가 다르지?"
2. **엣지 독 퇴화**: 🌳이 사이드패널에 흡수되면 엣지 독 개념 붕괴
3. **미니멀리즘 위배**: 사이드패널 = 추가 공간 = 복잡도 증가

## 6. 핵심 질문: "우리 서비스는 무엇인가?"

### 6-1. 정체성 재확인

> **"트리 구조 대화 관리 시스템"**

이 정체성을 유지하려면:
1. **트리**가 핵심임을 시각적으로 보여줘야 함
2. 🌳 엣지 독이 항상 보이면 "트리 기반"이라는 것을 상기시킴
3. 사이드패널로 바꾸면 "트리"가 다른 기능들 사이에 묻힘

### 6-2. 설정/계정이 정체성에 미치는 영향

| 시나리오 | 정체성 영향 |
|----------|-------------|
| 설정/계정 없음 | 정체성 유지, 사용자 불편 |
| 헤더 우측 아이콘 | 정체성 유지, 사용자 편의 |
| 좌측 사이드패널 | 정체성 희석 위험 |

### 6-3. 미니멀리즘 vs 발견성

| 가치 | 설명 | 이 토론에서 |
|------|------|-------------|
| **미니멀리즘** | 필요한 것만 보여주기 | 설정/계정은 숨겨도 됨 |
| **발견성** | 기능을 쉽게 찾을 수 있게 | 설정/계정이 보여야 함 |

**우선순위 제안**: 미니멀리즘 > 발견성
- 설정/계정은 빈도 낮음
- 숨겨도 "찾으면 있음"으로 충분

## 8. 키워드 사전

| 키워드 | 설명 |
|--------|------|
| 핵심 기능 | 없으면 서비스가 성립 안 되는 기능 |
| 부가 기능 | 핵심을 보조하는 기능 |
| 확장 기능 | 있으면 좋지만 없어도 되는 기능 |
| 관리 기능 | 시스템 레벨 조정 (설정, 계정) |
| 제품 정체성 | "이 서비스는 OOO이다" |
| 미니멀리즘 | 필요한 것만 남기기 ≠ 적게 |
| 기능의 Why | 이 기능이 왜 존재하는가 |
| 3-Layer 모델 | 핵심/부가/확장 기능 분류 |

## 9. 신규 이슈: 홈 화면 서비스 철학 문제점 (2026-02-03 추가)

### 9-1. 현재 홈 화면의 철학적 모순

**문제**: "마케팅 전략" 드롭다운이 초기 화면에서 무의미

```
┌────────────────────────────────────────────────────────────┐
│ 🧠 [마케팅 전략 ∨]                           ⚙️    [DK]   │
├────────────────────────────────────────────────────────────┤
│                      내 작업공간                           │
│                   생각을 가지치기하세요                    │
│      🔍 작업공간 검색...           [+ 새 작업공간]         │
│                                                            │
└────────────────────────────────────────────────────────────┘
     ↑
     "마케팅 전략"이 뭐지? 아직 작업공간이 없는데?
```

### 9-2. 서비스 철학적 분석

**뷰(View)의 정체성 문제**:

| 뷰 | 정체성 | 헤더 상태 |
|----|--------|----------|
| **홈** | "작업공간 목록" | 드롭다운 숨기기 or "작업공간 선택" |
| **작업공간 내부** | "특정 작업공간" | 드롭다운 표시 (현재 작업공간 이름) |

**현재 문제**: 홈인데 작업공간 내부처럼 보임

### 9-3. 기능의 "Why" 재검토

| 기능 | Why | 홈에서 필요? |
|------|-----|-------------|
| 작업공간 드롭다운 | 작업공간 간 빠른 전환 | ❌ (이미 목록이 보임) |
| "+ 새 작업공간" 버튼 | 새 작업공간 생성 | ✅ 핵심 CTA |
| 검색창 | 작업공간 찾기 | ✅ 목록이 많을 때 필요 |

**결론**: 홈에서 드롭다운은 **중복 기능** (목록 + 드롭다운 = 같은 기능 2개)

### 9-4. 코드 수준 원인 (철학적 관점)

**모듈 B와 모듈 C의 역할 혼란**:

```javascript
// 모듈 B: 홈 화면 (작업공간 목록)
// 모듈 C: 작업공간 드롭다운 (빠른 전환용)
```

**문제**:
- 모듈 B의 `goHome()`이 헤더 상태를 제대로 관리하지 않음
- 모듈 C의 드롭다운이 홈에서도 활성화되어 있음
- 두 모듈이 같은 데이터를 다른 UI로 보여주지만 연동되지 않음

### 9-5. 서비스 철학적 해결 방향

**원칙**: "한 화면에서 같은 기능은 한 번만"

| 상태 | 작업공간 접근 방식 | 헤더 드롭다운 |
|------|-------------------|--------------|
| 홈 | 목록에서 선택 | 숨기기 or 비활성화 |
| 작업공간 내부 | 드롭다운으로 전환 | 활성화 |

**개선안**:
```javascript
// 모듈 B goHome()
goHome() {
  // 헤더 드롭다운 숨기기
  document.getElementById('workspace-selector')?.setAttribute('hidden', '');
  // 로고 텍스트 표시
  document.querySelector('.logo-text')?.removeAttribute('hidden');
}
```

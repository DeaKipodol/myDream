# 민수 - UX 전문가 (사용자 심리 특화)

> UX/UI 전문가로서 인지심리학, 행동경제학, 사용자 동기 분석에 특화
> 핵심 질문: "사용자가 **왜** 이 행동을 하는가?"

---

## 1. 페르소나 프로필

**이름**: 민수
**직군**: UX/UI 전문가
**특화 분야**: 사용자 심리, 인지 부하, 행동 패턴, 동기 분석
**다른 전문가와의 관계**: 수진(시각), 동현(철학), 지은(통합)과 함께 UX 토론 진행

### 분석 프레임워크

| 개념 | 설명 | 적용 |
|------|------|------|
| **인지 부하** | 사용자가 처리해야 할 정보량 | 선택지 3개 이하 원칙 |
| **동기 분류** | 불안(확인 욕구) vs 호기심(탐색 욕구) | 접근 빈도와 위치 결정 |
| **심리적 안전** | 실수해도 되돌릴 수 있다는 확신 | Undo, 체크포인트 |

## 2. 프로젝트 이해: "AI 생각 작업공간"

### 2-1. 서비스 핵심 컨셉

> **"트리 구조 대화 관리 시스템"** - 여러 대화 경로를 동시에 관리하고, 참조하고, 병합할 수 있는 AI 상담 도구

**기존 챗봇과의 차이**:
| 기존 챗봇 | 우리 시스템 |
|----------|------------|
| 선형 대화 (한 방향) | 트리 구조 (분기 가능) |
| 이전 대화 수정 불가 | 노드 클릭으로 경로 전환 |
| 단일 컨텍스트 | 여러 경로 참조 가능 |
| 대화 리셋 시 처음부터 | 체크포인트로 저장/복원 |

### 2-2. 핵심 기능 3가지

1. **트리 구조 대화**: 대화가 분기되어 여러 경로로 발전 가능
2. **경로 전환**: 노드 클릭 = 파일 시스템의 `cd` 명령어처럼 컨텍스트 전환
3. **다중 관점**: 한 질문에 여러 AI 페르소나가 각자 답변 (퍼실리테이터 + 전문가 구조)

### 2-3. 현재 UI 구조 (엣지 독 시스템)

```
┌────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +                     │ ← 헤더 (작업공간 탭)
├────────────────────────────────────────────────┤
│    │                                       │   │
│ 🌳 │                                       │ 💡│ ← 좌우 엣지 독
│    │         대화 영역 (채팅)              │   │
│    │                                       │ 🎭│
│    │                                       │ 📄│
├────────────────────────────────────────────────┤
│  [메시지 입력...] [➤]                          │
└────────────────────────────────────────────────┘
```

**엣지 독 역할**:
- **좌측 🌳 (생각 트리)**: 대화 구조 시각화, 경로 전환 - **"구조를 본다"**
- **우측 💡🎭📄 (관점 도구)**: 다양한 관점으로 사고 확장 - **"관점을 넓힌다"**

## 3. 사용자 심리 분석: 이 서비스에서 사용자 행동

### 3-1. 사용자의 3가지 행동 모드

| 행동 | 의미 | 도구 | 심리 상태 | 빈도 |
|------|------|------|-----------|------|
| **생각한다** | AI와 대화 | 채팅 (중앙) | 몰입 | 높음 |
| **구조를 본다** | 전체 파악/확인 | 🌳 트리 (좌측) | 불안 해소 | 중간 |
| **관점을 넓힌다** | 다른 시각 탐색 | 💡🎭📄 (우측) | 호기심 | 낮음 |

### 3-2. 불안-호기심 스펙트럼

```
[불안 해소] ◄─────────────────────────► [호기심 탐색]
   빠른 접근 필요                    탐색적 접근 허용
   1-tap                            2-tap 폴더

🌳 생각 트리 ◄─────────────► 💡🎭📄 관점 도구
```

**심리적 근거**:
- **🌳 생각 트리**: "내가 어디까지 했지?" → **불안 해소** → 빠른 접근(1-tap) 필요
- **💡🎭📄 관점 도구**: "다른 관점이 궁금하다" → **호기심** → 탐색적 접근(2-tap) 허용

### 3-3. 트리 구조 대화의 심리적 가치

**왜 사용자가 트리 구조를 원하는가?**

1. **후회 최소화**: "다른 방향으로 질문했으면 어땠을까?" → 분기로 탐색 가능
2. **컨텍스트 보존**: 이전 대화로 돌아가도 맥락이 유지됨 → **심리적 안전**
3. **비선형 사고 지원**: 생각은 선형이 아님, 분기하고 병합함

## 4. 토론 주제 분석: GPT 스타일 사이드패널 도입

### 4-1. GPT vs 우리 서비스 비교 (사용자 관점)

| 요소 | ChatGPT | AI 생각 작업공간 | 심리적 차이 |
|------|---------|------------------|-------------|
| **네비게이션** | 좌측 사이드패널 (토글식) | 상단 탭 + 좌우 엣지 독 | GPT: 익숙함 / 우리: 새로움 |
| **채팅 히스토리** | 사이드패널에 목록 | 없음 (탭으로 분리) | GPT: 한눈에 / 우리: 탭 전환 |
| **설정/계정** | 사이드패널 하단 계정 영역 | 미구현 | GPT: 명확 / 우리: 불명확 |
| **도구 접근** | 사이드패널 메뉴 | 좌우 엣지 독 | GPT: 통합 / 우리: 분산 |
| **프로젝트 관리** | 사이드패널 "프로젝트" 섹션 | 상단 탭 | 유사 |

### 4-2. 사용자가 설정/계정에 접근할 때의 심리

**GPT 사용자의 멘탈 모델**:
- "설정은 사이드패널 하단에 있다"
- "계정 정보는 프로필 아이콘을 클릭하면 나온다"

**우리 서비스 사용자의 현재 경험**:
- "설정이 어디 있지?" → **탐색 비용 발생** → 인지 부하 증가
- "계정 관리는 어디서?" → 발견 불가 → **불안/불편**

### 4-3. 설정/계정 기능의 심리적 분류

| 기능 | 동기 유형 | 빈도 | 심리 상태 | 접근 방식 |
|------|-----------|------|-----------|-----------|
| **테마 변경** | 호기심 | 매우 낮음 | "커스터마이징" | 2-tap |
| **계정 정보** | 확인 욕구 | 매우 낮음 | "내 상태 확인" | 2-tap |
| **로그아웃** | 의도적 행위 | 매우 낮음 | 명확한 목적 | 2-tap |
| **도움말** | 불안 해소 | 낮음 | "모르겠다" | 1-tap이 좋지만 2-tap도 가능 |

**결론**: 설정/계정은 **호기심/확인 영역** → 2-tap 허용 → **숨겨도 됨**

### 4-4. 사이드패널 도입 시 인지 부하 분석

**현재 (엣지 독 시스템)**:
```
네비게이션 영역 3개:
1. 상단 탭 (작업공간)
2. 좌측 엣지 독 (🌳 트리)
3. 우측 엣지 독 (💡🎭📄 관점)
```

**사이드패널 추가 시**:
```
네비게이션 영역 4개:
1. 좌측 사이드패널 (히스토리, 설정, 계정)
2. 상단 탭 (작업공간)
3. 좌측 엣지 독 (🌳 트리)  ← 중복?
4. 우측 엣지 독 (💡🎭📄 관점)
```

**힉의 법칙 (Hick's Law)**: 선택지 개수 ↑ → 결정 시간 ↑
- 4개 네비게이션 = **과밀** → 사용자 혼란

### 4-5. GPT 멘탈 모델 활용 vs 새로운 멘탈 모델 교육

**옵션 A: GPT 멘탈 모델 따르기**
- 장점: 학습 비용 0, 익숙함
- 단점: "GPT랑 뭐가 다르지?" 정체성 문제

**옵션 B: 새로운 멘탈 모델 교육**
- 장점: 차별화, 고유한 UX
- 단점: 학습 비용 발생, 온보딩 필요

**옵션 C: 하이브리드**
- 설정/계정만 GPT 스타일 (헤더 우측 드롭다운)
- 핵심 기능(트리, 관점)은 우리만의 엣지 독 유지

## 5. 초기 제안 (사용자 심리 관점)

### 제안 A: 헤더 우측 드롭다운 (권장)

```
┌──────────────────────────────────────────────────┐
│ 🧠 AI 생각 │ 탭1 │ 탭2 │ +          [⚙️] [👤]  │
└──────────────────────────────────────────────────┘
                                    ↓ 클릭 시
                              ┌────────────┐
                              │ 설정       │
                              │ 도움말     │
                              │ ────────── │
                              │ 계정 정보  │
                              │ 플랜       │
                              │ 로그아웃   │
                              └────────────┘
```

**심리적 근거**:
1. 설정/계정은 빈도 낮음 → 2-tap 허용 → 드롭다운으로 충분
2. 기존 엣지 독 시스템 유지 → 인지 부하 증가 없음
3. GPT 헤더 우측 패턴과 유사 → 부분적 멘탈 모델 활용

### 제안 B: 좌측 사이드패널 (🌳 흡수)

```
┌──────────────────────────────────────────────────┐
│ [≡] 🧠 AI 생각 │ 탭1 │ 탭2 │ +                   │
├──────────────────────────────────────────────────┤
│ + 새 작업공간  │                              │   │
│ ────────────   │                              │ 💡│
│ 🌳 생각 트리   │        채팅 영역             │   │
│   └ 노드들...  │                              │ 🎭│
│ ────────────   │                              │ 📄│
│ 📁 히스토리    │                              │   │
│ ────────────   │                              │   │
│ ⚙️ 설정        │                              │   │
│ 👤 계정        │                              │   │
└──────────────────────────────────────────────────┘
```

**심리적 근거**:
1. GPT 멘탈 모델 완전 활용 → 학습 비용 0
2. 🌳 트리가 사이드패널에 흡수 → 더 넓은 공간 확보
3. 모든 네비게이션이 좌측에 통합

**심리적 우려**:
1. "GPT랑 뭐가 다르지?" → 정체성 혼란
2. 엣지 독의 "조용한 존재감" 상실
3. 좌우 비대칭 (좌측 무거움)

## 6. 토론에서 다룰 질문

1. **사용자가 설정/계정에 접근할 때 느끼는 긴급성은?**
   - 긴급하면 1-tap → 항상 보이는 곳
   - 비긴급하면 2-tap → 숨겨도 됨

2. **GPT 사용 경험이 있는 사용자가 처음 왔을 때 혼란은?**
   - "채팅 히스토리 어디?" → 상단 탭 학습 필요
   - "설정은?" → 현재 없음 → 불안

3. **트리 구조 대화라는 핵심 가치를 인지하는 데 어떤 UI가 도움이 되는가?**
   - 엣지 독이 "트리 기반 서비스"라는 정체성을 시각화
   - 사이드패널로 바꾸면 "GPT 클론"으로 인식될 가능성

4. **"생각 정리 도구"에서 설정/계정의 심리적 중요도는?**
   - 핵심 기능 아님 → 숨겨도 됨
   - 하지만 "필요할 때 못 찾으면" 불안 발생

## 8. 신규 이슈: 홈 화면 문제점 분석 (2026-02-03 추가)

### 8-1. 현재 홈 화면 상태

```
┌────────────────────────────────────────────────────────────┐
│ 🧠 [마케팅 전략 ∨]                           ⚙️    [DK]   │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                      내 작업공간                           │
│                   생각을 가지치기하세요                    │
│                                                            │
│      🔍 작업공간 검색...           [+ 새 작업공간]         │
│                                                            │
│                  (작업공간 목록 없음)                      │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 8-2. 발견된 UX 이슈

| # | 이슈 | 심리적 영향 | 심각도 |
|---|------|-------------|--------|
| 1 | "+ 새 작업공간" 버튼 무반응 | **좌절감** - 행동했는데 피드백 없음 | 🔴 높음 |
| 2 | "마케팅 전략" 드롭다운 무반응 | **혼란** - 클릭 가능해 보이는데 반응 없음 | 🔴 높음 |
| 3 | 작업공간 목록 안 뜸 | **허탈함** - 빈 화면 = "뭘 해야 하지?" | 🟡 중간 |
| 4 | 초기 화면에서 "마케팅 전략" 드롭다운 무의미 | **인지 불일치** - 아직 작업공간이 없는데 이미 선택된 듯한 UI | 🟡 중간 |

### 8-3. 사용자 심리 분석

**"+ 새 작업공간" 버튼 무반응**:
- 사용자 기대: "클릭하면 새 작업공간이 생성된다"
- 현재 상황: 아무 반응 없음
- 심리 상태: **자기 효능감 저하** → "내가 뭘 잘못한 건가?"
- **UX 원칙 위반**: 피드백 법칙 (Every action should have a reaction)

**"마케팅 전략" 드롭다운 무의미**:
- 초기 화면에서 이 드롭다운의 역할이 불명확
- 작업공간이 없는 상태에서 "마케팅 전략"이 선택된 것처럼 보임
- **멘탈 모델 불일치**: "아직 아무것도 안 만들었는데 왜 이미 선택되어 있지?"

### 8-4. 코드 수준 원인 분석

**모듈 B (홈 화면) 문제**:
```javascript
// 찾는 ID: 'btn-new-workspace'
document.getElementById('btn-new-workspace')?.addEventListener('click', () => {
  this.createWorkspace();
});
```
- HTML에 해당 ID가 없거나, DOM이 준비되기 전에 바인딩 시도

**모듈 C (작업공간 드롭다운) 문제**:
```javascript
// 찾는 ID: 'workspace-selector-btn'
this.selectorBtn?.addEventListener('click', (e) => {
  this.toggle();
});
```
- selectorBtn이 null일 가능성
- 모듈 간 연동 실패 (ModuleB ↔ workspaceManager 연결 안 됨)

### 8-5. 심리적 해결 방향

| 문제 | 심리적 해결책 |
|------|--------------|
| 버튼 무반응 | 즉시 피드백 제공 (로딩 스피너, 성공 메시지) |
| 드롭다운 무의미 | 초기 화면에서는 숨기거나, "작업공간 선택" 텍스트로 변경 |
| 빈 목록 | Empty State 디자인: "첫 번째 작업공간을 만들어보세요" + CTA |

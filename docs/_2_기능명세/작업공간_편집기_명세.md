## 기능 개요

### 핵심 컨셉

**VSCode 수준의 안정적인 코드 편집기** + **Git 같은 버전 관리** + **AI 편집 제안 시스템**을 결합한 작업 공간.

AI가 파일을 멋대로 덮어쓰지 않고, **변경사항을 제안**하면 사용자가 **diff를 보고 승인/거부**하는 방식.

### 한 문장 요약

> "AI가 코드를 제안하면, Git diff처럼 변경사항을 확인하고, 원하는 부분만 적용할 수 있는 안전한 편집 환경"

### 메모장(Scratchpad)과의 차이

| 구분 | 메모장 (Scratchpad) | 작업 공간 (Workspace) |
|------|---------------------|----------------------|
| 목적 | 빠른 메모, 임시 | 실제 파일 편집 |
| 대상 | 짧은 텍스트 | 전체 코드 파일 |
| AI 역할 | 읽기만 | 편집 제안 |
| 버전 관리 | 간단한 이력 | Git 수준 diff/rollback |
| 지속성 | 세션 내 | 영구 저장 (파일 시스템) |
| 편집 방식 | 직접 타이핑 | AI 제안 + 사용자 승인 |

## 기존 도구의 문제점

### 1. Gemini Canvas 문제점

```
❌ 문제 1: AI가 멋대로 편집
사용자: "주석 추가해줘"
AI: (파일 전체를 다시 생성, 기존 내용 일부 날림)
사용자: "아! 이전 코드가 더 나았는데..."

❌ 문제 2: 새 요구 시 내용 초기화
사용자: "이제 테스트도 추가해줘"
AI: (이전 편집 내용 무시하고 새로 생성)
사용자: "방금 추가한 주석이 다 사라졌어..."

❌ 문제 3: 변경사항 확인 불가
AI가 무엇을 바꿨는지 알 수 없음
이전 버전으로 돌아갈 방법 없음
```

### 2. Cursor / Copilot 문제점

```
❌ 문제 1: 파일 전체 덮어쓰기
AI: (코드 제안)
사용자: 적용 → 파일 전체가 바뀜
사용자: "일부만 적용하고 싶은데..."

❌ 문제 2: Diff 확인 불편
- 인라인 제안은 보기 어려움
- 변경사항이 많으면 파악 힘듦
- 부분 적용 불가능
```

### 3. ChatGPT 코드 블록 문제점

```
❌ 문제 1: 복사-붙여넣기 피로
사용자: 코드 복사 → 에디터 열기 → 붙여넣기
반복...

❌ 문제 2: 버전 관리 불가
이전 버전 찾으려면 채팅 히스토리 뒤져야 함

❌ 문제 3: 멀티 파일 편집 불가
여러 파일 수정 시 하나씩 복붙해야 함
```

#### 1. 제안 → 검토 → 적용 워크플로우

```

사용자 지시 → AI 제안 → 사용자 검토 → 선택적 적용

            제안만 함    diff 확인    원하는 것만
```

## 핵심 원칙

### 1. 사용자 통제 (User Control)

**원칙**: AI는 제안만, 실행은 사용자

```javascript
// ❌ 나쁜 예 (기존 도구)
ai.editFile('server.py', changes);  // 바로 적용

// ✅ 좋은 예 (우리 시스템)
const proposal = ai.proposeChanges('server.py', instruction);
user.review(proposal);  // 사용자가 검토
if (user.approves()) {
  workspace.apply(proposal);
}
```

### 2. 투명성 (Transparency)

**원칙**: 무엇이 바뀌는지 명확히

```
AI 제안:
✅ 추가: 23줄
✅ 수정: 5줄
✅ 삭제: 2줄

영향받는 함수:
- login()
- validate_user()

테스트 필요:
- test_login_success()
- test_login_invalid_input()
```

### 3. 되돌릴 수 있음 (Reversibility)

**원칙**: 언제든 이전으로 복구 가능

```
모든 변경은 버전으로 저장
→ 언제든 이전 버전으로 롤백
→ 특정 변경만 취소(undo) 가능
→ 삭제된 코드도 히스토리에서 복구
```

### 4. 안정성 (Stability)

**원칙**: 예상치 못한 변경 없음

```
❌ 불안정: AI가 요청하지 않은 부분도 수정
✅ 안정적: 지시한 부분만 정확히 수정
           다른 부분은 절대 건드리지 않음
```

## AI 편집 워크플로우

### 전체 흐름

```
1. 사용자 지시
   "에러 핸들링 개선해줘"
   ↓

2. AI 분석
   - 현재 코드 읽기
   - 문제점 파악
   - 개선 방안 설계
   ↓

3. AI 제안 생성
   - 변경사항 계산 (diff)
   - 영향 범위 분석
   - 제안서 작성
   ↓

4. 사용자 검토
   - Diff 뷰어로 확인
   - 변경사항 이해
   - 부분/전체 선택
   ↓

5. 적용
   - 승인된 변경만 적용
   - 버전 히스토리에 기록
   - 테스트 실행 (선택)
   ↓

6. 결과 확인
   - 편집기에 반영
   - 변경사항 요약 표시
```

### 코드 예시

```python
# workspace_manager.py

class WorkspaceManager:
    """작업 공간 관리"""

    def request_ai_edit(
        self,
        file_path: str,
        instruction: str
    ) -> EditProposal:
        """
        AI에게 편집 요청

        Args:
            file_path: 편집할 파일
            instruction: 편집 지시사항

        Returns:
            EditProposal: AI 편집 제안
        """
        # 1. 현재 파일 읽기
        current_content = self.read_file(file_path)

        # 2. AI에게 제안 요청
        prompt = f"""
        현재 코드:
        {current_content}

        요청사항:
        {instruction}

        변경사항을 unified diff 형식으로 제안해주세요.
        """

        ai_response = self.ai_client.chat(prompt)

        # 3. Diff 파싱
        diff = self.parse_diff(ai_response)

        # 4. 제안 객체 생성
        proposal = EditProposal(
            file_path=file_path,
            original_content=current_content,
            diff=diff,
            instruction=instruction,
            timestamp=datetime.now()
        )

        return proposal

    def apply_proposal(
        self,
        proposal: EditProposal,
        selected_changes: List[int] = None
    ):
        """
        편집 제안 적용

        Args:
            proposal: 편집 제안
            selected_changes: 적용할 변경사항 인덱스
                            (None이면 전체 적용)
        """
        # 1. 이전 버전 저장 (롤백용)
        version = self.version_manager.create_version(
            file_path=proposal.file_path,
            content=proposal.original_content,
            description=f"AI: {proposal.instruction}"
        )

        # 2. 변경사항 적용
        if selected_changes is None:
            # 전체 적용
            new_content = self.apply_diff(
                proposal.original_content,
                proposal.diff
            )
        else:
            # 선택한 것만 적용
            new_content = self.apply_partial_diff(
                proposal.original_content,
                proposal.diff,
                selected_changes
            )

        # 3. 파일 쓰기
        self.write_file(proposal.file_path, new_content)

        # 4. 이벤트 발생
        self.emit('file_changed', {
            'file_path': proposal.file_path,
            'version': version.id,
            'changes': selected_changes or 'all'
        })
```

```python
            file_path,
            version.content,
            f"롤백: {version.description}"
        )
```

## Diff 뷰어 구현

### Unified Diff 파싱

```python
def parse_unified_diff(diff_text: str) -> List[Change]:
    """
    Unified diff 형식 파싱

    Args:
        diff_text: diff 텍스트

    Returns:
        Change 객체 리스트
    """
    changes = []
    current_hunk = None

    for line in diff_text.split('\n'):
        if line.startswith('@@'):
            # 새 hunk 시작
            current_hunk = parse_hunk_header(line)
        elif line.startswith('-'):
            # 삭제된 줄
            changes.append(Change(
                type='delete',
                line_number=current_hunk.old_start,
                content=line[1:]
            ))
        elif line.startswith('+'):
            # 추가된 줄
            changes.append(Change(
                type='add',
                line_number=current_hunk.new_start,
                content=line[1:]
            ))
        else:
            # 변경 없는 줄 (컨텍스트)
            changes.append(Change(
                type='context',
                line_number=current_hunk.old_start,
                content=line[1:] if line.startswith(' ') else line
            ))

    return changes
```

### 1. 스마트 병합 (Smart Merge)

```python
# 사용자가 파일을 직접 편집하는 동안 AI 제안이 들어온 경우

def smart_merge(
    original: str,
    user_edit: str,
    ai_proposal: str
) -> MergeResult:
    """
    3-way 병합

    Args:
        original: 원본 내용
        user_edit: 사용자 편집 후
        ai_proposal: AI 제안

    Returns:
        병합 결과 (충돌 포함)
    """
    # Git 3-way merge 알고리즘 사용
    user_diff = diff(original, user_edit)
    ai_diff = diff(original, ai_proposal)

    # 충돌 감지
    conflicts = find_conflicts(user_diff, ai_diff)

    if not conflicts:
        # 충돌 없음 - 자동 병합
        return auto_merge(user_diff, ai_diff)
    else:
        # 충돌 있음 - 사용자 선택 필요
        return MergeResult(
            merged_content=None,
            conflicts=conflicts,
            requires_manual_resolution=True
        )
```

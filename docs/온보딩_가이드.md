## 🎯 프로젝트 핵심 정리 (5분)

### 한 문장 요약
> **"트리 구조 대화 관리 시스템 - 여러 대화 경로를 동시에 관리하고, 참조하고, 병합할 수 있는 AI 상담 도구"**

### 기존 챗봇과의 차이점

| 기존 챗봇 | 우리 시스템 |
|----------|------------|
| 선형 대화 (한 방향) | 트리 구조 (분기 가능) |
| 이전 대화 수정 불가 | 노드 클릭으로 경로 전환 |
| 단일 컨텍스트 | 여러 경로 참조 가능 |
| 대화 리셋 시 처음부터 | 체크포인트로 저장/복원 |

### 핵심 컨셉 3가지

#### 1. 트리 구조 대화
```
[Root]
  ├─ [질문1] → [답변1]
  │   ├─ [질문2a] → [답변2a]  ← 경로 A
  │   └─ [질문2b] → [답변2b]  ← 경로 B
  └─ [질문3] → [답변3]
```

#### 2. 경로 전환
- 노드를 클릭하면 그 노드까지의 경로로 전환
- AI는 새 경로의 맥락으로 대화 재개
- 마치 파일 시스템에서 `cd` 명령어처럼 동작

#### 3. 획기적인 기능들
- **크로스노드 참조**: 다른 경로의 내용을 현재 질문에 참조
- **분기 병합**: 두 대화 경로를 LCA 기반으로 통합
- **다중 관점**: 한 질문에 여러 AI 페르소나가 각자 답변

## 🏗️ 아키텍처 빠른 이해 (10분)

### 디렉토리 구조

```
myDream/
├── core/                    # 핵심 비즈니스 로직 (CLI 독립적)
│   ├── models.py            # Node, Tree 데이터 구조
│   ├── store.py             # 상태 관리 (tree + active_path + checkpoints)
│   ├── conversation.py      # 대화 관리 (1 turn = 1 node)
│   ├── path_utils.py        # 경로 유틸리티
│   ├── checkpoint.py        # 체크포인트 관리
│   └── ai_client.py         # OpenAI API 통합
│
├── cli/                     # CLI 레이어
│   ├── cli.py               # REPL + 17개 명령어
│   └── visualizer.py        # 트리/경로 시각화
│
├── tests/                   # 테스트 (133개, 81% 커버리지)
│   ├── test_models.py
│   ├── test_store.py
│   ├── test_conversation.py
│   └── ...
│
├── docs/                    # 문서
└── ai-thinking-workspace/   # 프론트엔드 프로토타입
```

### 핵심 클래스 관계

```
ConversationManager
    ↓ (사용)
Store ← tree: Tree
    ↓     active_path_ids: List[str]
    ↓     checkpoints: Dict[str, str]
    ↓
Tree ← nodes: Dict[str, Node]
    ↓
Node ← id, parent_id, user_question, ai_answer
```

### 데이터 흐름

```
1. 사용자 명령 (CLI)
   ↓
2. cli.py가 파싱
   ↓
3. ConversationManager 호출
   ↓
4. Store 상태 변경
   ↓
5. AI 필요시 ai_client 호출
   ↓
6. 결과 반환 및 출력
```

## 🎮 기본 사용법 (10분 실습)

### 시나리오: 첫 대화 트리 만들기

```bash
# 1. 첫 질문
> ask "Python과 JavaScript의 차이점은?"
✅ 노드 생성: n1 (새 노드)
🤖 AI 답변: ...

# 2. 트리 확인
> tree
Root
└─ n1: Python과 JavaScript의 차이점은?

# 3. 이어서 질문 (n1의 자식)
> ask "그럼 어느 것을 먼저 배워야 할까?"
✅ 노드 생성: n2 (n1의 자식)

# 4. 분기 만들기 (n1로 돌아가서 다른 질문)
> switch n1
✅ n1로 이동

> ask "TypeScript는 JavaScript와 어떻게 다른가?"
✅ 노드 생성: n3 (n1의 자식)

# 5. 트리 확인 (분기 생성됨!)
> tree
Root
└─ n1: Python과 JavaScript의 차이점은?
    ├─ n2: 그럼 어느 것을 먼저 배워야 할까?
    └─ n3: TypeScript는 JavaScript와 어떻게 다른가?

# 6. 체크포인트 저장
> checkpoint save javascript_learning
✅ 체크포인트 저장: javascript_learning → n3

# 7. 경로 확인
> path
Root → n1 → n3
```

## 💡 자주 하는 질문 (FAQ)

### Q1: "노드를 삭제할 수 있나요?"
**A**: Phase CLI-1에서는 미지원. Phase CLI-2에서 reparent 기능과 함께 추가 예정.

### Q2: "여러 사람이 동시에 사용할 수 있나요?"
**A**: 현재는 단일 사용자. 협업 기능은 백로그에 등록되어 있음.

### Q3: "웹 UI는 언제 나오나요?"
**A**: Phase UI-1 예정 (10-14일 소요). 프론트엔드 프로토타입은 이미 완성.

### Q4: "다른 AI 모델(Claude, Gemini)도 사용할 수 있나요?"
**A**: 현재는 OpenAI만 지원. 추후 확장 가능한 구조.

### Q5: "대화 트리가 너무 커지면 성능은?"
**A**: 현재 테스트는 100개 노드까지 확인. 더 큰 규모는 최적화 필요.

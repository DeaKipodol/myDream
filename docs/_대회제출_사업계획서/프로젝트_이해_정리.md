## 1. 프로젝트 한 문장 요약

**"사용자가 사고하기 좋은 AI 서비스"**

부제: 트리 구조 대화 관리 시스템 - 여러 대화 경로를 동시에 관리하고, 참조하고, 병합할 수 있는 AI 상담 도구

### 패러다임 전환

> **기존**: AI를 **비서**로 생각 (일을 시키고 사람은 아무것도 안 함)
>
> **우리**: AI는 내 머릿속 생각을 **시각화**하고 **발전**시켜주는 **도구**
>
> **핵심**: AI는 "사고"를 돕는 "도구"

---

## 2. 핵심 문제 정의 (5가지)

### 문제 1: 선형적 대화 구조

**증상**: 대화가 한 방향으로만 진행, 다른 방향 탐색 시 새로 시작해야 함

**구체적 사례**:
```
상황: 투자할 기업 5개의 자료를 AI에게 주고 각 기업 분석 요청

1번 기업 심도 깊은 대화
→ 2번 기업 대화
→ 3번 기업 대화
→ 1번 기업 내용이 가물가물...

AI에게 물어보면 엉뚱한 답변 (현재 맥락과 섞임)
→ 스크롤을 올려서 기존 대화를 찾아야 함
→ 수백 턴의 대화 = 스크롤 30번 이상 필요
```

### 문제 2: 자료 업로드 제한

**증상**: 올릴 수 있는 파일 개수가 한정적

**제한 현황**:
- **ChatGPT / Grok**: 약 20개 파일
- **DeepSeek**: 약 50개 파일 (문맥 이해 능력 높음)

**구체적 사례**:
```
상황: 분석해야 할 기업이 100개

→ AI 도움 필요 (사람이 다 읽기 어려움)
→ 하지만 파일 개수 제한에 막힘
→ 문서 패턴 파악 및 데이터 분할 기술 필요
```

**근본 원인**: AI의 문맥 이해 용량 한계

### 문제 3: 단일 관점

AI가 하나의 관점만 제공 → 다양한 시각에서 분석 어려움

### 문제 4: 자료 연결 불편

시각적으로 문서를 보면서 AI와 대화하기 어려움

### 문제 5: 대화 종료 후 휘발되는 인간 지능

대화 종료 시 사고 과정이 사라짐 → 복원 불가

---

## 2-1. 문제의 근본 원인

> **AI를 "비서"로 생각**해서 나온 문제들
>
> - 일을 시키고 사람은 아무것도 안 하는 바람
> - 사용자의 "사고 과정"을 지원하지 않음

---

## 2-2. 우리가 해결하는 방법

✅ **트리 구조 대화** - 한 질문에서 여러 답변 분기 가능
✅ **주제 분류 & 시각화** - 사고 전개 과정을 시각적으로 표시
✅ **경로 전환** - 잘못된 첫 시점으로 가서 올바른 방향 지도
✅ **RAG 시스템** - 자료 업로드 한계 제거 (400개 파일 경험)
✅ **다중 관점 (페르소나 모드)** - 여러 AI 전문가가 각자 답변
✅ **크로스노드 참조** - 다른 경로의 내용을 현재 질문에 참조

## 3. 핵심 솔루션 (2가지)

### 솔루션 1: 주제 분류 & 시각화 (트리 구조)

**어떻게 작동하나?**

1. **대화 진행 중 주제 자동 분석 및 분류**
   ```
   [Root]
     ├─ [기업1 분석] → [답변1]
     │   ├─ [재무제표] → [답변2a]
     │   └─ [시장점유율] → [답변2b]
     ├─ [기업2 분석] → [답변3]
     └─ [기업3 분석] → [답변4]
   ```

2. **분류된 주제 클릭 → 해당 대화 시작 부분으로 즉시 이동**
   - 스크롤 30번 → 클릭 1번
   - 시각적으로 사고 전개 과정 확인 가능

3. **이전과 다른 질문 가능 (분기 생성)**
   - AI가 의도를 잘못 해석한 첫 시점으로 이동
   - 올바른 방향으로 지도 가능
   - 기존 경로는 보존 (삭제되지 않음)

**효과**:
- ✅ 선형적 대화 구조 문제 해결
- ✅ 사고 과정 시각화
- ✅ 이전 대화 찾기 용이 (스크롤 불필요)

---

### 솔루션 2: RAG 시스템 (자료 제한 제거)

**실제 구현 경험**:
- **한라대학교 RAG 시스템** 구축
- **400여개 파일**, 수천 가지 문서 학습
- 문서 패턴 파악 및 데이터 분할 기술 개발

**핵심 성과**:
> **자료 업로드 한계를 없앴습니다**

**기술적 해결**:
- AI의 문맥 이해 용량 한계 (20~50개) → RAG로 극복
- 필요한 정보만 동적으로 검색해서 제공
- 사용자는 무제한 파일 업로드 가능

**효과**:
- ✅ 자료 업로드 제한 문제 해결
- ✅ 대량 문서 분석 가능 (100개 기업도 가능)
- ✅ AI의 자료 이해력 향상

---

### 솔루션 3: 다중 관점 (Persona Mode)

**어떻게 작동하나?**:
- 한 질문에 여러 AI 전문가가 각자 답변
- 예: 마케터, 분석가, 비평가가 동시에 의견 제시
- 전문가별 색상 구분 말풍선으로 시각화

**효과**:
- ✅ 단일 관점 문제 해결
- ✅ 다양한 시각에서 문제 분석

## 4. 기술 아키텍처

### Backend (Python)

```
core/           # 핵심 비즈니스 로직
├── models.py       # Node, Tree 데이터 구조
├── store.py        # 상태 관리 (tree + active_path + checkpoints)
├── conversation.py # 대화 관리 (1 turn = 1 node)
├── checkpoint.py   # 체크포인트 관리
└── ai_client.py    # OpenAI API 통합

cli/            # CLI 인터페이스
├── cli.py          # REPL 메인 루프
└── visualizer.py   # 트리 시각화
```

### Frontend (Vanilla JS - 프로토타입)

```
ai-thinking-workspace/
├── js/
│   ├── chat.js     # 대화 모드 전환, 메시지 렌더링
│   ├── panel.js    # 전문가 관리 (초대/해제)
│   └── app.js      # 엣지 독, 패널 토글
└── css/
    └── style.css   # GPT 스타일 레이아웃
```

## 6. 차별화 요소

### 핵심 차별화

> **다른 기업들이 AI를 "비서"로 대하면서 발생하는 문제들을 계속 발굴하고 해결**
>
> → "사용자가 사고하기 좋은 AI 서비스" 구축

### vs ChatGPT / DeepSeek / 두바오
| 항목 | 기존 서비스 | 우리 시스템 |
|------|---------|------------|
| **패러다임** | AI = 비서 | AI = 사고 도구 |
| **대화 구조** | 선형 (스크롤 지옥) | 트리 (클릭 이동) |
| **사고 과정** | 휘발 (보이지 않음) | 시각화 (트리로 표현) |
| **자료 제한** | 20~50개 | 무제한 (RAG) |
| **경로 탐색** | 불가 | 여러 경로 동시 관리 |
| **다중 관점** | 없음 | 페르소나 모드 |

### vs Manus (메타 인수)
| 항목 | Manus | 우리 시스템 |
|------|-------|------------|
| **해결 문제** | 동기식 → 비동기식 | 선형 → 트리 구조 |
| **핵심 가치** | 자동 다단계 작업 | 사고 과정 시각화 |
| **타겟** | 반복 작업 자동화 | 복잡한 사고/의사결정 |

### vs Notion AI
| 항목 | Notion AI | 우리 시스템 |
|------|-----------|------------|
| **대화 관리** | 문서 내 단발성 | 트리 구조 영구 관리 |
| **경로 탐색** | 불가 | 여러 경로 동시 탐색 |
| **컨텍스트 참조** | 페이지 단위 | 노드 단위 크로스 참조 |

### 우리의 독창성

**1. 사고 과정을 시각화**
- 기존: 대화 히스토리만 쌓임 (휘발성)
- 우리: 트리 구조로 사고 전개 과정 표현

**2. RAG 기반 무제한 자료**
- 기존: 문맥 이해 용량 한계 (20~50개)
- 우리: 400개 파일 학습 경험 기반 기술

**3. 패러다임 전환**
- 기존: AI에게 일을 시킴
- 우리: AI와 함께 생각함

## 7. 타겟 고객

### 1차 타겟: 얼리어답터

**정의**: GPT 출시 후 4년 동안 AI를 깊게 사용한 사용자

**특징**:
- 채팅 방식의 불편함을 이미 체감 중
- 자신만의 사용법 개발 중
- 더 나은 도구를 찾고 있음

**페인 포인트**:
- 스크롤 지옥 (수백 턴 대화에서 특정 내용 찾기)
- 자료 업로드 제한 (20~50개)
- 사고 과정 휘발

### 2차 타겟: 일반 사용자

> **5년이 지난 지금, 얼리어답터가 느낀 불편함을 일반 사용자도 느끼는 시점**
>
> 아직 느끼지 못한 분들도 곧 느끼게 될 것

### 주요 타겟 직군

1. **투자 분석가 / 컨설턴트**
   - 여러 기업/시나리오 동시 분석
   - 대량 자료 처리 필요

2. **연구자 / 작가**
   - 다양한 아이디어 브레인스토밍
   - 사고 과정 보존 필요

3. **의사결정자 (경영진)**
   - 선택지별 결과 탐색
   - 다중 관점 필요

4. **교육자**
   - 학생별 맞춤형 대화 경로 관리

### 사용 시나리오

**시나리오 1: 투자 분석**
```
5개 기업 자료 업로드
→ 각 기업별 심층 분석
→ 기업1 내용 다시 확인 필요
→ 주제 클릭으로 즉시 이동 (스크롤 불필요)
```

**시나리오 2: 전략 기획**
```
"A안과 B안 중 어떤 게 나을까?"
→ 두 경로로 분기 후 비교
→ A안에서 잘못된 가정 발견
→ 해당 노드로 이동, 수정 후 재분기
```

**시나리오 3: 연구 작업**
```
100개 논문 업로드 (RAG)
→ 주제별 요약 요청
→ 특정 주제에 대해 다중 관점 (페르소나 모드)
→ 사고 과정 트리로 저장
```

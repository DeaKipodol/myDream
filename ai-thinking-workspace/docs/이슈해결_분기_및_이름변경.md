## 이슈 #1: 분기점 표시 스타일 개선

### 문제 상황
대화 히스토리에서 분기점을 나타내는 표시가 너무 눈에 띄어서 대화 흐름을 방해함.

**Before:**
```
[대화 1]
[AI 응답 1]
┌────────────────────────────────────┐
│ 🌿 "useEffect 훅"로 진행            │  ← 너무 눈에 띄는 노란 바
└────────────────────────────────────┘
[대화 2]
```

### 해결 방법
분기점 표시를 더 작고 미묘하게 변경.

**After:**
```
[대화 1]
[AI 응답 1]
↳ useEffect 훅  ← 작고 투명한 텍스트
[대화 2]
```

### 변경 코드

**파일:** `css/style.css`

```css
/* Before */
.branch-indicator {
  padding: 6px 14px;
  background: linear-gradient(135deg, var(--primary-light) 0%, rgba(180, 149, 106, 0.1) 100%);
  border: 1px dashed var(--primary);
  font-size: 11px;
  opacity: 0.8;
}

/* After */
.branch-indicator {
  padding: 2px 8px;
  background: transparent;
  border: none;
  font-size: 10px;
  opacity: 0.5;
}
```

**파일:** `js/chat.js`

```javascript
// 아이콘 변경: 🌿 → ↳

`;
```

## 이슈 #2: 분기 생성 위치 오류

### 문제 상황
중간 메시지에서 "🌿 분기" 버튼을 클릭해도 항상 **맨 마지막 노드**에서 분기가 생성됨.

**시나리오:**
```
[메시지 1: 마케팅 전략]  ← 여기서 분기 버튼 클릭
[메시지 2: 타겟 고객]
[메시지 3: 20대 분석]   ← 실제로는 여기서 분기 생성됨 (잘못됨)
```

### 원인 분석

**기존 코드 (`chat.js`):**
```javascript
handleBranchAction(messageEl) {
  // ❌ 항상 현재 노드(맨 마지막)에서 분기 생성
  let currentNodeId = workspace?.currentNode;

  window.treeManager.createBranch(currentNodeId, branchName);
}
```

**문제점:**
- 클릭한 메시지의 노드 ID를 사용하지 않음
- 항상 `workspace.currentNode` (맨 마지막 노드) 사용

### 해결 방법

각 메시지에 노드 ID를 저장하고, 클릭한 메시지의 노드 ID로 분기 생성.

**변경 코드:**

**1. 메시지에 노드 ID 추가 (`chat.js`)**

```javascript
// switchToNode() 메서드
path.forEach((pathNode, index) => {
  if (pathNode.conversation && answer) {
    const aiMsg = this.renderMessage({
      type: 'ai',
      content: `<p>${answer}</p>`,
      nodeId: pathNode.id  // ✅ 노드 ID 전달
    });
    this.messagesContainer.insertAdjacentHTML('beforeend', aiMsg);
  }
});
```

**2. HTML에 data 속성으로 저장 (`chat.js`)**

```javascript
// renderStandardMessage() 메서드
const nodeIdAttr = msg.nodeId ? `data-node-id="${msg.nodeId}"` : '';

return `
  <div class="message ai-message standard-mode" ${nodeIdAttr}>
    ...
  </div>
`;
```

**3. 클릭한 메시지의 노드 ID 사용 (`chat.js`)**

```javascript
handleBranchAction(messageEl) {
  // ✅ 클릭한 메시지의 노드 ID 가져오기
  let parentNodeId = messageEl.dataset.nodeId;

  // 노드 ID가 없으면 현재 노드 사용 (하위 호환성)
  if (!parentNodeId) {
    const workspace = window.workspaceStore.getCurrentWorkspace();
    parentNodeId = workspace?.currentNode;
  }

  console.log('[ChatManager] 분기 생성 대상 노드:', parentNodeId);

  window.treeManager.createBranch(parentNodeId, branchName);
}
```

### 결과

```
[메시지 1: 마케팅 전략]  ← 분기 버튼 클릭
  └─ [새 분기]           ← ✅ 여기서 분기 생성됨!

[메시지 2: 타겟 고객]   ← 분기 버튼 클릭
  └─ [새 분기]           ← ✅ 여기서 분기 생성됨!

[메시지 3: 20대 분석]   ← 분기 버튼 클릭
  └─ [새 분기]           ← ✅ 여기서 분기 생성됨!
```

## 이슈 #3: 노드 이름 변경 시 채팅 헤더 미업데이트

### 문제 상황
노드 이름을 변경하면 트리는 업데이트되지만, 채팅 헤더 제목은 그대로 유지됨.

**재현 단계:**
1. 노드 우클릭 → "이름 변경"
2. "새 이름" 입력
3. 확인

**결과:**
- 트리 뷰: ✅ "새 이름"으로 업데이트
- 채팅 헤더: ❌ 여전히 "옛날 이름"

### 원인 분석

#### 1. EventBus 아키텍처

우리 프로젝트는 **EventBus** (커스텀 구현)를 사용한 Pub/Sub 패턴:

```
발행자 (_init.js)           EventBus              구독자 (chat-header.js)
     │                         │                           │
     │  emit('NODE_CHANGED')   │                           │
     ├────────────────────────>│                           │
     │                         │  callback 실행            │
     │                         ├──────────────────────────>│
     │                         │                           │
     │                         │              채팅 헤더 제목 업데이트
```

**EventBus 위치:** `js/core/event-bus.js` (직접 구현)

**주요 메서드:**
- `emit(event, data)` - 이벤트 발행
- `on(event, callback)` - 이벤트 구독
- `once(event, callback)` - 일회성 구독
- `enableLogging(true)` - 디버깅 로그

#### 2. 채팅 헤더가 제목을 업데이트하는 방법

**파일:** `js/modules/chat-header.js`

```javascript
// 구독: NODE_CHANGED 이벤트 대기 중 👂
EventBus.on(EVENTS.NODE_CHANGED, ({ nodeId, nodeName }) => {
  this.setCurrentNode(nodeId, nodeName);  // 제목 업데이트
});
```

채팅 헤더는 **수동적**:
- "누군가 NODE_CHANGED 이벤트를 발생시켜주면"
- "그때 제목을 업데이트할게요"

#### 3. 원래 코드의 문제

**파일:** `js/_init.js` (수정 전)

```javascript
CoreEventBus.on(EVENTS.CHATHEADER_MENU, ({ nodeId, action }) => {
  switch (action) {
    case 'rename':
      const newName = prompt('새 이름 입력:');
      if (newName && window.workspaceStore) {
        const workspace = window.workspaceStore.getCurrentWorkspace();
        const node = findNodeInTree(workspace.tree, nodeId);
        if (node) {
          node.text = newName;  // 1. 데이터 변경
          window.workspaceStore.updateTree(workspace.id, workspace.tree);  // 2. 저장

          if (window.treeManager) {
            window.treeManager.render(workspace);  // 3. 트리 UI 업데이트
          }

          // ❌ NODE_CHANGED 이벤트 발생 안 함!
          // → 채팅 헤더가 모르고 있음
        }
      }
      break;
  }
});
```

**문제:**
- 트리 데이터 ✅
- 트리 UI ✅
- 채팅 헤더 알림 ❌ ← **핵심 문제**

### 해결 방법

NODE_CHANGED 이벤트를 발생시켜 채팅 헤더에게 알림.

**단, 조건부로:**
- **현재 보고 있는 노드**를 변경 → 채팅 헤더 업데이트 필요
- **다른 노드**를 변경 → 채팅 헤더 업데이트 불필요

### 변경 코드

**파일:** `js/_init.js` (수정 후)

```javascript
case 'rename':
  const newName = prompt('새 이름 입력:');
  if (newName && newName.trim() && window.workspaceStore) {
    const workspace = window.workspaceStore.getCurrentWorkspace();
    const node = findNodeInTree(workspace.tree, nodeId);
    if (node) {
      // 1. 데이터 변경
      node.text = newName.trim();

      // 2. conversation도 동기화 (대화 내용에서도 보이는 이름)
      if (node.conversation) {
        node.conversation.question = newName.trim();
      }

      // 3. 저장
      window.workspaceStore.updateTree(workspace.id, workspace.tree);

      // 4. 트리 UI 업데이트
      if (window.treeManager) {
        window.treeManager.render(workspace);
      }

      // 5. ✅ 현재 보고 있는 노드라면 채팅 UI도 업데이트
      if (workspace.currentNode === nodeId) {
        // 채팅 헤더에게 알림 📢
        CoreEventBus.emit(EVENTS.NODE_CHANGED, {
          nodeId: nodeId,
          nodeName: newName.trim()
        });

        // 채팅 내용도 새로고침 (대화 내 질문 텍스트 업데이트)
        if (window.chatManager) {
          window.chatManager.switchToNode(nodeId);
        }
      }

      console.log('[Bridge] 노드 이름 변경됨:', nodeId, '->', newName.trim());
    }
  }
  break;
```

### 작동 흐름 비교

#### Before (버그)

```
사용자: "타겟 고객" → "고객 분석"으로 변경
├─ 1. node.text = "고객 분석" ✅
├─ 2. workspaceStore.updateTree() ✅
├─ 3. treeManager.render() ✅ (트리 업데이트)
└─ 4. ❌ 채팅 헤더는 모르고 있음
        └─ 여전히 "타겟 고객" 표시
```

#### After (수정)

```
사용자: "타겟 고객" → "고객 분석"으로 변경
├─ 1. node.text = "고객 분석" ✅
├─ 2. node.conversation.question = "고객 분석" ✅
├─ 3. workspaceStore.updateTree() ✅
├─ 4. treeManager.render() ✅ (트리 업데이트)
├─ 5. workspace.currentNode === nodeId? YES!
│   ├─ CoreEventBus.emit(NODE_CHANGED) 📢
│   │   └─ 채팅 헤더가 듣고 있음 👂
│   │       ├─ setCurrentNode("고객 분석") ✅
│   │       └─ render() (제목 업데이트) ✅
│   └─ chatManager.switchToNode() ✅ (대화 내용 새로고침)
```

### Case 분석

**Case 1: 현재 보고 있는 노드 이름 변경**

```

결과:

├─ 채팅 헤더: "고객 분석" ✅
```

## 📚 관련 개념

### EventBus (Pub/Sub 패턴)

**위치:** `js/core/event-bus.js`

**특징:**
- 직접 구현 (외부 라이브러리 없음)
- 모듈 간 느슨한 결합 통신
- 디버깅 기능 내장 (히스토리, 로깅)

**주요 메서드:**
```javascript
// 발행
EventBus.emit('NODE_CHANGED', { nodeId, nodeName });

// 구독
EventBus.on('NODE_CHANGED', ({ nodeId, nodeName }) => {
  console.log('노드 변경:', nodeName);
});

// 구독 해제
const unsubscribe = EventBus.on('test', callback);
unsubscribe();

// 디버깅
EventBus.enableLogging(true);
EventBus.getHistory(10);
EventBus.getSubscribers();
```

**장점:**
- 발행자와 구독자가 서로 몰라도 됨
- 하나의 이벤트를 여러 곳에서 들을 수 있음
- 코드 추가/제거가 쉬움

## 📝 배운 점

1. **UI 동기화는 이벤트 기반으로**
   - 데이터 변경 → 이벤트 발생 → 관련 UI들이 자동 업데이트
   - 하드코딩된 의존성 없이 확장 가능

2. **data 속성 활용**
   - DOM 요소에 메타데이터 저장 (`data-node-id`)
   - 클릭 이벤트에서 컨텍스트 정보 추출 가능

3. **조건부 이벤트 발생**
   - 모든 경우에 이벤트를 발생시킬 필요 없음
   - 필요한 경우만 선택적으로 발생

4. **디버깅 우선 설계**
   - EventBus에 로깅, 히스토리 기능 내장
   - 문제 발생 시 추적 용이

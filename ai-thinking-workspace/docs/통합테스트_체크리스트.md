## 🎯 우선순위 테스트 (Critical Path)

### 시나리오 1: 첫 사용자 - 작업공간 생성부터 대화까지

```
사용자 행동                          기대 결과
─────────────────────────────────────────────────────────
1. 페이지 로드                        → 홈 화면 표시
2. 좌측 햄버거 버튼 클릭              → 사이드패널 열림
3. "새 작업공간" 버튼 클릭            → prompt 입력창
4. "마케팅 전략" 입력 후 확인         → 새 탭 생성 + 채팅 화면
5. 채팅 입력창에 질문 입력            → AI 응답 표시
6. 응답 호버                          → 액션 버튼 표시 (복사, 👍, 🌿 분기, 전문가)
```

**테스트 포인트:**
- [ ] 햄버거 클릭 시 사이드패널 애니메이션
- [ ] 작업공간 생성 후 자동으로 탭 열림
- [ ] 채팅 입력창 활성화 상태 확인
- [ ] AI 응답 후 액션 버튼 호버 시 표시

**알려진 이슈:**
- ⚠️ 목업 데이터가 별도 탭에 뜬다는 사용자 피드백 (TabManager UX 개선 필요)

## 🔧 모듈별 통합 테스트

### A. Core 모듈 (Wave 1)

#### Store + EventBus 통합

**시나리오: 상태 변경 시 이벤트 발행**

```javascript
// 1. 탭 전환
store.setState({ activeTabId: 't2' });
→ EventBus: TAB_SWITCHED 발생? (아님, 직접 emit 필요)
→ 구독자들 반응?

// 2. 노드 변경
CoreEventBus.emit(EVENTS.NODE_CHANGED, { nodeId, nodeName });
→ ChatHeader.setCurrentNode() 호출?
→ 제목 업데이트?
```

**테스트:**
- [ ] Store.setState() 후 subscribe 리스너 호출
- [ ] EventBus.emit() 후 on() 구독자 호출
- [ ] EventBus 로깅 활성화 후 콘솔 확인
```javascript
EventBus.enableLogging(true);
```

#### StateMachine + TabManager 통합

**시나리오: 탭 로딩 상태 관리**

```javascript
// 탭 생성
tabManager.createTab('ws-123', '작업공간');
→ IDLE → transition('LOAD') → LOADING
→ _loadTabData() 실행
→ 성공: LOADING → transition('SUCCESS') → READY
→ 실패: LOADING → transition('FAIL') → ERROR
```

**테스트:**
- [ ] 탭 생성 시 로딩 스피너 표시 (LOADING 상태)
- [ ] 로딩 완료 시 스피너 제거 (READY 상태)
- [ ] 로딩 실패 시 느낌표 표시 (ERROR 상태)
- [ ] ERROR 상태에서 재시도 시 다시 LOADING
- [ ] TAB_STATE_CHANGED 이벤트 발행 확인

### B. UI 모듈 (Wave 2)

#### TabManager + SidePanel 연동

**시나리오: 사이드패널에서 작업공간 선택**

```
사이드패널 열기
→ 작업공간 클릭
→ EventBus.emit(SIDEPANEL_WORKSPACE_SELECT)
→ TabManager._subscribeEvents()에서 수신
→ tabManager.openWorkspace() 호출
→ 기존 탭 있으면 switchTab(), 없으면 createTab()
```

**테스트:**
- [ ] 사이드패널에서 작업공간 클릭 → 새 탭 생성
- [ ] 이미 열린 작업공간 클릭 → 해당 탭으로 전환
- [ ] 탭 생성 후 사이드패널 자동 닫힘

#### ChatHeader + TreeManager 연동

**시나리오: 채팅 헤더 노드명 클릭**

```
채팅 헤더 "📍 현재 노드명" 클릭
→ EventBus.emit(CHATHEADER_NAVIGATE)
→ EdgeDock._subscribeEvents()에서 수신
→ edgeDock.openPanel('tree') 호출 (독이 보일 때만)
→ 트리 뷰 표시
```

**테스트:**
- [ ] 노드명 클릭 → 트리 패널 열림 (독이 보일 때)
- [ ] 사이드패널 열려있으면 독이 숨겨진 상태 → 클릭해도 트리 안 열림
- [ ] 트리 패널에서 현재 노드 하이라이트

#### EdgeDock + SidePanel 충돌 방지

**시나리오: 패널 간 상호 배타적 동작**

```
사이드패널 열기
→ EventBus.emit(SIDEPANEL_OPEN)
→ EdgeDock._subscribeEvents()에서 수신
→ edgeDock.hide() 호출
→ 독 + 열린 패널 모두 숨김

사이드패널 닫기
→ EventBus.emit(SIDEPANEL_CLOSE)
→ edgeDock.show() 호출
→ 독 다시 표시 (단, 패널은 닫힌 상태 유지)
```

**테스트:**
- [ ] 사이드패널 열기 → 독 사라짐
- [ ] 사이드패널 닫기 → 독 다시 나타남
- [ ] 독 패널 열린 상태에서 사이드패널 열기 → 독 패널도 닫힘

### 이슈 #1: 분기점 표시 스타일

**Before:**
```css
.branch-indicator {
  padding: 6px 14px;
  background: linear-gradient(...);
  border: 1px dashed var(--primary);

}
```

**After:**

```css
  background: transparent;
  border: none;
  opacity: 0.5;
}
```

**테스트:**

- [ ] 대화 흐름을 방해하지 않음
- [ ] 아이콘이 "↳"로 표시

### 이슈 #2: 분기 생성 위치 오류

**Before:**
```javascript
// 항상 workspace.currentNode에서 분기 생성
let parentNodeId = workspace?.currentNode;
```

**After:**
```javascript
// 클릭한 메시지의 노드 ID로 분기 생성
let parentNodeId = messageEl.dataset.nodeId;
```

**테스트:**
- [ ] 첫 번째 메시지에서 분기 → 해당 위치에 생성
- [ ] 중간 메시지에서 분기 → 해당 위치에 생성
- [ ] 마지막 메시지에서 분기 → 해당 위치에 생성
- [ ] 콘솔에서 `[ChatManager] 분기 생성 대상 노드` 로그 확인

---

### 이슈 #3: 노드 이름 변경 시 채팅 헤더 미업데이트

**Before:**
```javascript
// NODE_CHANGED 이벤트 발생 안 함
node.text = newName;
window.workspaceStore.updateTree(...);
window.treeManager.render(...);
```

**After:**
```javascript
// 현재 노드일 때만 NODE_CHANGED 이벤트 발생
if (workspace.currentNode === nodeId) {
  CoreEventBus.emit(EVENTS.NODE_CHANGED, { nodeId, nodeName });
  chatManager.switchToNode(nodeId);
}
```

**테스트:**
- [ ] 현재 노드 이름 변경 → 채팅 헤더 즉시 업데이트
- [ ] 다른 노드 이름 변경 → 채팅 헤더 그대로
- [ ] 이름 변경 후 대화 내용 질문 텍스트도 업데이트
- [ ] conversation.question 동기화 확인

## 🔍 데이터 흐름 검증

### 1. 작업공간 생성 흐름

```
사용자 입력: "마케팅 전략"
↓
SidePanel._onNewWorkspace()
↓
workspaceStore.createWorkspace("마케팅 전략")
↓
EventBus.emit(SIDEPANEL_WORKSPACE_SELECT, { workspaceId, workspaceName })
↓
TabManager.openWorkspace(workspaceId, workspaceName)
↓
createTab() → createTabState() → createTabStateMachine()
↓
EventBus.emit(TAB_CREATED)
↓
_loadTabData() → IDLE → LOAD → LOADING
↓
_fetchWorkspace(workspaceId) → workspaceStore.getWorkspace()
↓
SUCCESS → READY
↓
EventBus.emit(TAB_STATE_CHANGED, { status: 'ready' })
↓
ChatHeader render() → 정상 상태 UI
```

**검증 포인트:**
- [ ] workspaceStore.createWorkspace() 호출 확인
- [ ] 새 탭 ID 생성 (`tab-{timestamp}`)
- [ ] StateMachine 전이 순서: IDLE → LOADING → READY
- [ ] TAB_STATE_CHANGED 이벤트 3회 발행 (IDLE, LOADING, READY)
- [ ] ChatHeader 로딩 → 정상 UI 전환

---

### 2. 노드 전환 흐름

```
트리에서 노드 클릭
↓
TreeManager._onNodeClick()
↓
EventBus.emit(NODE_SWITCHED, { nodeId, nodePath })
↓
_init.js에서 수신
↓
workspaceStore.setCurrentNode(workspaceId, nodeId)
↓
chatManager.switchToNode(nodeId)
↓
path = _getNodePath(tree, nodeId)  // 루트부터 현재까지
↓
path.forEach(pathNode => renderMessage({ nodeId: pathNode.id }))
↓
각 메시지에 data-node-id 속성 추가
↓
스크롤을 하단으로
```

**검증 포인트:**
- [ ] _getNodePath()가 올바른 경로 반환
- [ ] 각 메시지에 data-node-id 속성 존재
- [ ] 분기점 표시 정확한 위치에 삽입
- [ ] 스크롤 위치가 하단 (scrollToBottom 호출)

# UX 토론 & 디자인 변화 히스토리

**작성일**: 2026-01-29
**대상**: ai-thinking-workspace/ 토글바 → 엣지 독 전환 과정
**핵심 문제**: 하단 토글바가 전송 버튼을 가리는 Critical 이슈 해결

---

## 1. 페르소나 정리

### 1차 토론 (3인)

| 역할 | 전문 분야 | 관점 핵심 |
|------|-----------|-----------|
| **사용자 심리 전문가** | 인지 부하, 행동 패턴, 불안/호기심 동기 | "사용자가 왜 이걸 누르는가" — 심리적 동기 기반 설계 |
| **디자인/효과 전문가** | 시각 피드백, 마이크로인터랙션, figure-ground | "어떻게 보여야 하는가" — 시각적 위계와 공간 분리 |
| **서비스 철학 전문가** | 제품 정체성, 기능 분류, 미니멀리즘 | "이 서비스는 무엇인가" — 기능의 본질적 분류 |

### 2차 토론 (4인, +1 추가)

| 역할 | 이름 | 추가 역할 |
|------|------|-----------|
| **통합/종합 전문가** | 지은 | 3인의 관점을 종합, 취사선택, 구현 우선순위 결정 |

## 2. 디자인 변화 시간순 기록

### v0 — 원본: 하단 플로팅 토글바

```
┌─────────────────────────┐
│   채팅 메시지 영역        │
├─────────────────────────┤
│  [메시지 입력...] [➤]   │
├─────────────────────────┤
│  [🌳] [🎭] [📄]         │  ← 하단 fixed 토글바
└─────────────────────────┘
```

**문제**: 토글바가 전송 버튼(➤)을 가림. Critical 이슈.
- 데스크톱: 간격 좁아 오탭
- 모바일: 키보드 올라오면 완전 차단
- iPhone: 홈 인디케이터와 겹침

---

### v1 시도 — 인라인 배치 (입력 위)

**변경**: 토글 버튼을 채팅 입력 바로 위에 인라인 배치
**의도**: 겹침 해결 + 채팅 영역과의 근접성

```
┌─────────────────────────┐
│   채팅 메시지 영역        │
├─────────────────────────┤
│  🌳 🎭 📄               │  ← 인라인 (좌측 정렬)
│  [메시지 입력...] [➤]   │
└─────────────────────────┘
```

**사용자 피드백**: "개 별로임"
- 버튼이 박스 형태를 잃고 텍스트 목록처럼 보임
- 플로팅 때 있던 "추가 기능" 느낌이 사라짐
- 시각적 위계가 무너짐 (Figure-Ground 분리 실패)

**결론**: ❌ 즉시 롤백

---

### v2 시도 — 헤더 우측 통합 (Plan A)

**변경**: 🌳🎭📄 아이콘을 헤더 우측에 배치 (3인 토론 결론)
**의도**: 하단 영역 완전 해방, 글로벌 도구로 승격

```
┌──────────────────────────────────┐
│ 🧠 AI 생각 | 탭1 | 탭2 | 🌳🎭📄 │  ← 헤더에 통합
├──────────────────────────────────┤
│   채팅 메시지 영역                │
├──────────────────────────────────┤
│  [메시지 입력...] [➤]           │
└──────────────────────────────────┘
```

**사용자 피드백** (2가지 문제):
1. "이전 플로팅이 직관적이고 추가 기능처럼 보였는데, 우측 상단에선 어떤 기능인지 알 수 없음"
   — **Figure-Ground 효과 상실**: 떠있을 때는 "별도 레이어 = 부가 도구"로 인지, 헤더에 합쳐지면 정체 불명
2. "작업공간 탭이 상단에 메뉴바처럼 고정된 것도 깔끔하지 않음"
   — **시각적 과밀**: 작업공간 탭 + 토글 아이콘이 한 줄에 몰려 복잡

**결론**: ❌ 완전 롤백 (HTML/CSS/JS 모두 원복)

---

### 핵심 발견 (사용자 인사이트)

롤백 후 사용자가 직접 디자인 원칙을 제시:

> **"미니멀 디자인을 추구하면서 숨기되, 누가 봐도 숨겨져있는 게 보여서 누르면 나타나게. 약간 폴더처럼. 하위와 상위로 구분하는 게 필요. 이때 우리 서비스의 성격을 잘 분류해야 — 이것은 이 사용자의 이것을 도와주기 위한 것이다."**

이 인사이트에서 도출된 원칙:
- **숨기되 보이게** = Progressive Disclosure
- **폴더처럼 계층** = 1-tap / 2-tap 구조
- **서비스 성격 분류** = 사용자 행동 기반 기능 분류

---

### 4인 토론 결론: 서비스 기능 분류

사용자의 3가지 행동 모드로 기능 분류:

| 행동 | 의미 | 도구 | 심리 상태 | 접근 빈도 |
|------|------|------|-----------|-----------|
| **생각한다** (Thinking) | 대화 | 채팅 (중앙) | 몰입 | 항상 |
| **구조를 본다** (Structuring) | 전체 파악 | 🌳 트리 (좌측) | 불안/확인 | 높음 |
| **관점을 넓힌다** (Expanding) | 시야 확장 | 💡🎭📄 (우측) | 호기심 | 낮음 |

**좌우 분리 근거**:
- 좌 = 과거/구조 (이미 만든 것 확인) → 불안 해소 → 빠른 접근(1-tap) 필요
- 우 = 미래/확장 (새 관점 탐색) → 호기심 → 탐색적(2-tap 폴더) 허용

### v3 구현 — 엣지 독 (현재)

```
┌──────────────────────────────────┐
│ 🧠 AI 생각 | 탭1 | 탭2 |        │
├──────────────────────────────────┤
│    │                        │    │
│ 🌳 │   채팅 메시지 영역      │ 💡 │  ← 좌우 엣지 독
│    │                        │    │
│    │                        │ 🎭 │  ← (💡 클릭 시 펼침)
│    │                        │ 📄 │
├──────────────────────────────────┤
│  [메시지 입력...] [➤]           │
└──────────────────────────────────┘
```

**설계 원칙**:
- 화면 가장자리에 붙어 "존재하지만 조용한" 상태
- hover → 라벨 노출 (뭔지 알 수 있음)
- 클릭 → 패널 슬라이드 (폴더 열기)
- 1-tap (🌳) vs 2-tap 폴더 (💡→🎭/📄) 비대칭

**사용자 피드백**: "사용 편의성이 높아졌다" ✅

---

### v3.1 패치 — 시인성 & 닫기

**문제 2가지**:
1. 엣지 독이 처음에 잘 안 보임 (배경과 구분 부족)
2. 트리 열고 나서 다시 닫을 수 없음 (좌측 독이 숨겨짐)

**수정**:
1. 시인성: 버튼 48px, 그림자 추가, 테두리 강화, 라벨 기본 표시(opacity 0.7)
2. 닫기: 사이드바 열려도 좌측 독 유지 (🌳 재클릭으로 닫기)

| 버전 | 변경 | 이유 | 결과 |

## 4. 도출된 디자인 원칙

1. **Figure-Ground 분리**: 부가 도구는 메인 콘텐츠와 시각적으로 분리된 레이어에 있어야 "추가 기능"으로 인지됨
2. **Progressive Disclosure**: 처음엔 아이콘만, hover시 라벨, 클릭시 전체 패널
3. **행동 기반 배치**: 기능의 위치는 사용자의 심리 상태(불안/호기심)와 빈도가 결정
4. **1-tap/2-tap 비대칭**: 빈도 높은 도구는 즉시 접근, 낮은 도구는 폴더 탐색 허용
5. **헤더 통합 금지**: 네비게이션/도구를 헤더에 합치면 정체성과 Figure-Ground 모두 상실
